### ขั้นที่ 1.1.2 Docker คืออะไร

> 🎯 **ขั้นนี้จะได้:** เข้าใจว่าทำไมเราเปิด MySQL ผ่าน Docker

📖 Docker คือ "กล่อง" ที่มีโปรแกรมติดตั้งพร้อมใช้อยู่ข้างใน เราไม่ต้องติดตั้ง MySQL ลงเครื่องเอง แค่สั่ง Docker ให้เปิดกล่อง MySQL ขึ้นมา

| คำ | แปลว่า | เปรียบเหมือน |
|---|---|---|
| **image** | แม่แบบของกล่อง เช่น `mysql:8.4` | แผ่นติดตั้งโปรแกรม |
| **container** | กล่องที่เปิดใช้งานจริงจาก image | โปรแกรมที่กำลังเปิดอยู่ |
| **volume** | ที่เก็บข้อมูลนอกกล่อง | ฮาร์ดดิสก์ภายนอก ลบกล่องแล้วข้อมูลไม่หาย |
| **docker compose** | คำสั่งเปิดหลายกล่องพร้อมกันตามไฟล์ `docker-compose.yml` | รีโมตที่เปิดทุกเครื่องในห้องด้วยปุ่มเดียว |

ข้อดี
- ทุกเครื่องได้ MySQL เวอร์ชันเดียวกัน (เครื่องครู เครื่องนักเรียน เครื่องกรรมการ)
- พังแล้วลบทิ้ง สร้างใหม่ได้ใน 1 นาที

> ❗ **ก่อนใช้คำสั่ง `docker` ต้องเปิดโปรแกรม Docker Desktop ก่อนทุกครั้ง** รอจนไอคอนรูปวาฬที่มุมจอขึ้นว่า "Engine running"

### ขั้นที่ 1.3.1 สร้างโฟลเดอร์หลักและเริ่ม Git

> 🎯 **ขั้นนี้จะได้:** โฟลเดอร์ `Eva_Learn` ที่ Git เริ่มเก็บประวัติแล้ว

📖 **Git** คือโปรแกรมเก็บประวัติโค้ด ทุกครั้งที่ `commit` = ถ่ายรูปโค้ดตอนนั้นเก็บไว้ ย้อนกลับได้เสมอ และใช้ส่งงานขึ้น GitLab ของกรรมการ (บท 13)

⌨️ **ทำตาม**
1. สร้างโฟลเดอร์ `C:\Eva_Learn`
2. ใน VS Code เลือก **File → Open Folder** เปิดโฟลเดอร์นี้
3. เปิด terminal แล้วพิมพ์

```bash
git init
```

✅ **ต้องเห็น:** `Initialized empty Git repository in C:/Eva_Learn/.git/`

> 💡 Git สร้างโฟลเดอร์ซ่อนชื่อ `.git` ไว้เก็บประวัติ **ห้ามลบ** ถ้าลบ ประวัติทั้งหมดหาย

### ขั้นที่ 1.3.2 สร้างไฟล์ .gitignore

> 🎯 **ขั้นนี้จะได้:** Git ไม่เก็บไฟล์ลับและไฟล์ขนาดใหญ่ที่สร้างใหม่ได้

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `.gitignore` ที่โฟลเดอร์หลัก (ชื่อขึ้นต้นด้วยจุด ไม่มีนามสกุล)

```gitignore
node_modules/
.env
.env.local
.next/
backend/uploads/*
!backend/uploads/.gitkeep
backend/backups/
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | ไม่เก็บโฟลเดอร์ `node_modules` ทุกที่ | package ที่ npm โหลดมา ใหญ่หลายร้อย MB สร้างใหม่ได้ด้วย `npm install` |
| 2 | ไม่เก็บไฟล์ `.env` | มีรหัสผ่านฐานข้อมูลและ JWT secret ถ้าขึ้น Git คนอื่นเห็นหมด **(กรรมการตรวจเรื่องนี้)** |
| 3 | ไม่เก็บ `.env.local` | ไฟล์ค่าลับของ Next.js (เผื่อไว้) |
| 4 | ไม่เก็บโฟลเดอร์ `.next` | Next.js สร้างเองทุกครั้งที่รัน |
| 5 | ไม่เก็บทุกไฟล์ใน `backend/uploads` | ไฟล์หลักฐานที่ผู้ใช้อัปโหลด เป็นข้อมูลไม่ใช่โค้ด |
| 6 | **ยกเว้น** ไฟล์ `.gitkeep` ให้เก็บ | Git ไม่เก็บโฟลเดอร์ว่าง ไฟล์ว่างนี้ทำให้คนที่ clone ไปมีโฟลเดอร์ uploads พร้อมใช้ |
| 7 | ไม่เก็บโฟลเดอร์ `backend/backups` | ไฟล์สำรองข้อมูล (บท 11) อาจมีข้อมูลส่วนตัว |

🧩 **Syntax ใหม่: รูปแบบในไฟล์ .gitignore**

```syntax
[v:ชื่อไฟล์]
[v:ชื่อโฟลเดอร์][s:/]
[v:โฟลเดอร์][s:/*]
[s:!][v:ไฟล์ที่ยกเว้น]
```

| รูปแบบ | แปลว่า | ตัวอย่าง |
|---|---|---|
| `ชื่อ` | ไม่เก็บไฟล์/โฟลเดอร์ชื่อนี้ ทุกที่ในโปรเจกต์ | `.env` |
| `ชื่อ/` | `/` ท้าย = เฉพาะ **โฟลเดอร์** | `node_modules/` |
| `โฟลเดอร์/*` | `*` = "อะไรก็ได้" → ทุกไฟล์ในโฟลเดอร์นั้น | `backend/uploads/*` |
| `!ชื่อ` | `!` = **ยกเว้น** กลับมาเก็บ (ต้องอยู่ใต้บรรทัดที่สั่งไม่เก็บ) | `!backend/uploads/.gitkeep` |

- 1 บรรทัด = 1 กฎ
- ใช้ `/` คั่นโฟลเดอร์เสมอ (แม้บน Windows)
- บรรทัดที่ขึ้นต้นด้วย `#` คือคอมเมนต์

✅ **ลองเลย:** ใน VS Code แถบซ้าย ชื่อไฟล์ `.gitignore` ต้องขึ้น (ตรวจผลจริงในขั้น 1.8.1)

## 1.4 ไฟล์ค่าตั้งค่า .env

### ขั้นที่ 1.4.1 สร้างไฟล์ .env.example

> 🎯 **ขั้นนี้จะได้:** ไฟล์ตัวอย่างค่าตั้งค่า ที่ขึ้น Git ได้ (ไม่มีรหัสจริง)

📖 **ทำไมต้องมี 2 ไฟล์?**
- `.env` = ค่าจริง มีรหัสผ่าน → **ไม่ขึ้น Git**
- `.env.example` = แม่แบบ บอกว่าต้องมีค่าอะไรบ้าง → **ขึ้น Git** คนที่ clone ไปจะคัดลอกเป็น `.env` แล้วใส่ค่าของตัวเอง

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `.env.example` ที่โฟลเดอร์หลัก

```ini
# ใช้ร่วมกันทั้ง docker-compose และ backend (คัดลอกเป็น .env แล้วแก้รหัสผ่าน/JWT_SECRET)

# ฐานข้อมูล
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=change_me
DB_NAME=eva_db
DB_CONTAINER=eva_mysql

# Backend (port ของ API)
PORT=5000
JWT_SECRET=change_me_to_long_random_text
JWT_EXPIRES_IN=8h

# Frontend (port ของหน้าเว็บ ตอนรันด้วย docker compose)
WEB_PORT=3000
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ค่า | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1, 3, 11, 16 | คอมเมนต์ | อธิบายว่าแต่ละกลุ่มคืออะไร |
| 4 | `DB_HOST` เครื่องที่ MySQL อยู่ | backend ใช้ต่อฐานข้อมูล (`localhost` = เครื่องนี้) |
| 5 | `DB_PORT` port ของ MySQL | ทั้ง docker-compose (เปิด port) และ backend (ต่อ port) ใช้ค่าเดียวกัน |
| 6-7 | `DB_USER` / `DB_PASSWORD` | docker-compose ใช้ตั้งรหัส root ตอนสร้าง MySQL, backend ใช้ login เข้า MySQL |
| 8 | `DB_NAME` ชื่อฐานข้อมูล | docker-compose สร้างฐานข้อมูลชื่อนี้ให้, backend ใช้ฐานข้อมูลนี้ |
| 9 | `DB_CONTAINER` ชื่อกล่อง MySQL | ตั้งชื่อ container และใช้ตอน Backup ข้อมูล (บท 11) |
| 12 | `PORT` | port ของ backend (บท 03) |
| 13 | `JWT_SECRET` | "กุญแจ" เซ็นบัตรผ่าน (token) ตอน login (บท 04) ใครรู้ค่านี้ปลอม token ได้ **ต้องเป็นความลับ** |
| 14 | `JWT_EXPIRES_IN` | token หมดอายุใน 8 ชั่วโมง ต้อง login ใหม่ |
| 17 | `WEB_PORT` | port ของหน้าเว็บ ตอนรันทั้งระบบด้วย Docker (บท 13) |

🧩 **Syntax ใหม่: ไฟล์ .env**

```syntax
[n:ชื่อค่า][s:=][v:ค่า]
[s:#] [v:คอมเมนต์]
```

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `DB_HOST` | 🟢 ตั้งเอง | ชื่อค่า นิยมใช้ตัวใหญ่ คั่นคำด้วย `_` โค้ดจะเรียกด้วยชื่อนี้ เช่น `process.env.DB_HOST` |
| `=` | ⚪ เครื่องหมาย | คั่นชื่อกับค่า |
| `localhost` | 🟠 ค่า | ค่าที่เก็บ ไม่ต้องใส่ `" "` |

กฎที่ต้องจำ
- **ห้ามเว้นวรรค** รอบ `=` → `PORT=5000` ✅ / `PORT = 5000` ❌
- 1 บรรทัด = 1 ค่า
- ค่าทุกตัวเป็น **ข้อความ** (โค้ดจะได้ `"5000"` ไม่ใช่ตัวเลข 5000)

## 1.5 เปิด MySQL ด้วย Docker

### ขั้นที่ 1.5.1 รู้จักรูปแบบไฟล์ YAML

> 🎯 **ขั้นนี้จะได้:** อ่านและเขียนไฟล์ `.yml` ได้ถูกรูปแบบ (ไฟล์นี้ผิดแค่ย่อหน้าเดียวก็รันไม่ได้)

📖 `docker-compose.yml` เขียนด้วยรูปแบบ **YAML** ซึ่งใช้ **การย่อหน้า** บอกว่าอะไรอยู่ข้างในอะไร (แทนวงเล็บ)

🧩 **Syntax ใหม่: YAML**

```syntax
[p:ชื่อ][s::] [v:ค่า]
[p:ชื่อกลุ่ม][s::]
  [p:ชื่อข้างใน][s::] [v:ค่า]
  [p:รายการ][s::]
    [s:-] [v:ค่าที่ 1]
    [s:-] [v:ค่าที่ 2]
```

| รูปแบบ | แปลว่า |
|---|---|
| `ชื่อ: ค่า` | ตั้งค่า ต้องมี **ช่องว่าง 1 ช่องหลัง `:`** |
| `ชื่อ:` แล้วขึ้นบรรทัดใหม่ย่อหน้า | กลุ่ม ของที่ย่อหน้าเข้าไปอยู่ในกลุ่มนี้ |
| `- ค่า` | รายการ (หลายค่า) แต่ละตัวขึ้นต้นด้วย `-` และเว้นวรรค |
| `${ชื่อ}` | ใช้ค่าจากไฟล์ `.env` (docker compose อ่าน `.env` ให้อัตโนมัติ) |
| `# ข้อความ` | คอมเมนต์ |

กฎที่ต้องจำ
- ย่อหน้าด้วย **ช่องว่าง 2 ช่อง** ต่อชั้น **ห้ามใช้ปุ่ม Tab**
- ของที่อยู่ระดับเดียวกัน ต้องย่อหน้าเท่ากันเป๊ะ
- ชื่อหลัง `:` ในไฟล์นี้เป็น 🟣 ที่ Docker กำหนด (เช่น `image`, `ports`) ต้องสะกดตาม ยกเว้นชื่อ service (เช่น `mysql`) ที่ตั้งเองได้

### ขั้นที่ 1.5.2 เริ่มไฟล์ docker-compose.yml: บอกว่าจะใช้กล่องอะไร

> 🎯 **ขั้นนี้จะได้:** ส่วนแรกของไฟล์ บอก Docker ว่าจะเปิดกล่อง MySQL รุ่นไหน ชื่ออะไร

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `docker-compose.yml` ที่โฟลเดอร์หลัก

```yaml
services:
  mysql:
    image: mysql:8.4
    container_name: ${DB_CONTAINER}
    restart: unless-stopped
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | เปิดกลุ่ม `services` (รายการกล่องที่จะเปิด) | ทุกกล่องต้องอยู่ใต้ services (บท 13 จะเพิ่มกล่อง backend, frontend) |
| 2 | ตั้งชื่อ service ว่า `mysql` (🟢 ตั้งเอง) | ใช้ตอนสั่ง `docker compose up -d mysql` |
| 3 | ใช้ image MySQL เวอร์ชัน 8.4 | ทุกเครื่องได้ MySQL รุ่นเดียวกัน |
| 4 | ตั้งชื่อกล่องตามค่า `DB_CONTAINER` ใน .env (= `eva_mysql`) | ใช้เรียกกล่องในคำสั่ง เช่น `docker exec eva_mysql …` |
| 5 | ถ้ากล่องหยุดเพราะ error หรือเปิดเครื่องใหม่ ให้เปิดเองอัตโนมัติ (เว้นแต่เราสั่งหยุดเอง) | ไม่ต้องคอยเปิด MySQL เองทุกวัน |

> 💡 สังเกตการย่อหน้า: `mysql:` ย่อ 2 ช่อง (อยู่ใน services) ส่วน `image:` ย่อ 4 ช่อง (อยู่ใน mysql)

### ขั้นที่ 1.5.3 ตั้งค่า MySQL: ภาษาไทย รหัสผ่าน port และที่เก็บข้อมูล

> 🎯 **ขั้นนี้จะได้:** ไฟล์ docker-compose.yml ที่ใช้งานได้จริง

⌨️ **พิมพ์โค้ด:** พิมพ์ต่อท้ายไฟล์ (ย่อหน้า `command:` ให้ตรงกับ `restart:`)

```yaml
    command:
      - --mysql-native-password=ON
      - --authentication-policy=mysql_native_password
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: ${DB_NAME}
      TZ: Asia/Bangkok
    ports:
      - "${DB_PORT}:3306"
    volumes:
      - mysql_data:/var/lib/mysql
      # รันอัตโนมัติตอนสร้างฐานข้อมูลครั้งแรก (schema.sql ก่อน seed.sql ตามตัวอักษร)
      - ./backend/sql:/docker-entrypoint-initdb.d

volumes:
  mysql_data:
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | รายการตัวเลือกตอนเปิด MySQL | - |
| 2-3 | ใช้วิธีเก็บรหัสผ่านแบบเดิม | ให้โปรแกรมเชื่อมต่อทุกตัว (HeidiSQL, DBeaver) เข้าได้ ไม่ติดปัญหา |
| 4-5 | ใช้ชุดตัวอักษร `utf8mb4` | **รองรับภาษาไทย** ถ้าไม่ใส่ ชื่อภาษาไทยจะกลายเป็น `????` |
| 6 | กลุ่มค่าที่ส่งให้ MySQL ตอนสร้าง | - |
| 7 | ตั้งรหัส root = ค่า `DB_PASSWORD` ใน .env | backend ใช้รหัสเดียวกันต่อเข้ามา |
| 8 | สร้างฐานข้อมูลชื่อ `DB_NAME` (= `eva_db`) ให้อัตโนมัติ | ไม่ต้องสั่ง `CREATE DATABASE` เอง |
| 9 | ตั้งเวลาเป็นเวลาไทย | **สำคัญ** ระบบเช็กว่าวันนี้อยู่ในช่วงเปิดประเมินไหม ถ้าเวลาเพี้ยน หัวข้ออาจปิดก่อนกำหนด |
| 10-11 | เปิด port: `port ของเครื่องเรา:port ในกล่อง` | backend ที่รันบนเครื่องเราต่อ MySQL ผ่าน `localhost:3306` ได้ |
| 12-13 | เก็บข้อมูลไว้ใน volume ชื่อ `mysql_data` | ปิด/ลบกล่องแล้วข้อมูลไม่หาย |
| 14 | คอมเมนต์ | - |
| 15 | เอาโฟลเดอร์ `backend/sql` ไปวางในจุดพิเศษของ MySQL | **ไฟล์ .sql ในโฟลเดอร์นี้ถูกรันอัตโนมัติตอนสร้างฐานข้อมูลครั้งแรก** (บท 02 จะสร้าง schema.sql, seed.sql) |
| 17-18 | ประกาศว่ามี volume ชื่อ `mysql_data` | ต้องประกาศไว้ล่างสุด ระดับเดียวกับ `services` (ไม่ย่อหน้า) |

🧩 **Syntax ที่ควรสังเกตในไฟล์นี้**

```syntax
[s:-] [v:"][s:${][n:DB_PORT][s:}][v::3306"]
```

- ค่าที่มี `:` อยู่ข้างใน (แบบ port) ให้ครอบด้วย `" "` กัน YAML สับสนว่าเป็น `ชื่อ: ค่า`
- `environment:` เป็นกลุ่มแบบ `ชื่อ: ค่า` ส่วน `command:`, `ports:`, `volumes:` เป็นรายการแบบ `- ค่า`
- `volumes:` มี 2 ที่: ข้างใน `mysql` (ย่อหน้า = ของกล่องนี้) และล่างสุด (ไม่ย่อหน้า = ประกาศ volume)

> 💡 ไฟล์นี้เป็น **ฉบับแรก** บท 13 จะเพิ่ม healthcheck และกล่อง backend, frontend เพื่อ deploy ทั้งระบบ ไฟล์ฉบับสมบูรณ์: [docker-compose.yml](../../docker-compose.yml)

## 1.6 เตรียม Backend

### ขั้นที่ 1.6.1 สร้าง package.json ของ backend

> 🎯 **ขั้นนี้จะได้:** ไฟล์ `backend/package.json` ที่บอกว่าโปรเจกต์ใช้ package อะไร และมีคำสั่งอะไรบ้าง

📖 **package.json** คือ "บัตรประจำตัว" ของโปรเจกต์ Node.js เก็บรายชื่อ package ที่ใช้ และคำสั่งลัด (scripts)

⌨️ **ทำตาม:**

```bash
cd backend
npm init -y
```

(`-y` = ตอบ "ใช่" ทุกคำถาม ใช้ค่าเริ่มต้น) แล้วเปิด `backend/package.json` แก้ให้เป็นแบบนี้

```json
{
  "name": "backend",
  "version": "1.0.0",
  "description": "Eva API",
  "main": "server.js",
  "scripts": {
    "dev": "nodemon server.js",
    "start": "node server.js",
    "test": "node --test \"tests/*.test.js\""
  },
  "license": "ISC",
  "type": "module"
}
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 2-4 | ชื่อ เวอร์ชัน คำอธิบายโปรเจกต์ | ข้อมูลประกอบ |
| 5 | ไฟล์เริ่มต้นคือ `server.js` | บอกว่าโปรแกรมเริ่มทำงานที่ไฟล์ไหน |
| 6-10 | คำสั่งลัด รันด้วย `npm run ชื่อ` | พิมพ์สั้นลง |
| 7 | `npm run dev` = รันด้วย nodemon | ตอนพัฒนา: แก้โค้ดแล้ว server รีสตาร์ทเอง |
| 8 | `npm start` = รันด้วย node ธรรมดา | ตอนใช้งานจริง (Docker ใช้คำสั่งนี้ บท 13) |
| 9 | `npm test` = รันไฟล์ทดสอบทุกไฟล์ในโฟลเดอร์ tests | บท 12 |
| 12 | `"type": "module"` | **สำคัญมาก** ทำให้เขียน `import x from "y"` ได้ (เรียกว่า ESM) โจทย์กำหนดให้ใช้แบบนี้ |

🧩 **Syntax ใหม่: JSON**

```syntax
[s:{]
  [v:"ชื่อ"][s::] [v:"ค่าข้อความ"][s:,]
  [v:"กลุ่ม"][s::] [s:{] [v:"ชื่อ"][s::] [v:"ค่า"] [s:}]
[s:}]
```

กฎที่ต้องจำ (JSON เข้มกว่า JavaScript)
- ชื่อ **ต้องอยู่ใน `" "` เสมอ** (ใช้ `' '` ไม่ได้)
- คั่นแต่ละรายการด้วย `,` แต่ **รายการสุดท้ายห้ามมี `,`** (ผิดบ่อยที่สุด)
- เขียนคอมเมนต์ไม่ได้
- ถ้าในข้อความมี `"` ต้องเขียนเป็น `\"` (แบบบรรทัด 9)

> ❗ **"type": "module" ห้ามลืม** ถ้าลืมจะเจอ `SyntaxError: Cannot use import statement outside a module` ในบท 03

### ขั้นที่ 1.6.2 ติดตั้ง package ของ backend

> 🎯 **ขั้นนี้จะได้:** package ทุกตัวที่ backend ต้องใช้ ถูกโหลดลง `node_modules`

⌨️ **ทำตาม:** (ยังอยู่ในโฟลเดอร์ backend)

📖 **`@5` คืออะไร?** = เลือกเวอร์ชันหลัก 5 ให้ตรงกับที่โค้ดในคู่มือเขียนไว้ ถ้าไม่ใส่ npm จะโหลดเวอร์ชันล่าสุด ซึ่งอาจเปลี่ยนวิธีใช้ไปแล้ว

| package | เอาไว้ทำอะไร | ใช้ในบท |
|---|---|---|
| `express` | สร้าง API | 03 |
| `cors` | ให้หน้าเว็บคนละ port เรียก API ได้ | 03 |
| `dotenv` | อ่านไฟล์ .env | 03 |
| `jsonwebtoken` | สร้าง/ตรวจบัตรผ่าน (JWT) ตอน login | 04 |
| `express-fileupload` | รับไฟล์อัปโหลด (หลักฐาน PDF) | 06 |
| `mysql2` | คุยกับ MySQL | 03 |
| `zod` | ตรวจข้อมูลที่ส่งมา | 04 |

### ขั้นที่ 1.7.3 ตั้งค่า next.config.mjs ให้ใช้ Tailwind

> 🎯 **ขั้นนี้จะได้:** Next.js ส่งไฟล์ CSS ผ่าน Tailwind ก่อนแสดงผล

⌨️ **พิมพ์โค้ด:** เปิด `frontend/next.config.mjs` **ลบของเดิมทั้งหมด** แล้วพิมพ์

```js
/** @type {import('next').NextConfig} */
const nextConfig = {
  turbopack: {
    rules: {
      "*.css": {
        loaders: ["@tailwindcss/turbopack"],
        as: "*.css",
      },
    },
  },
  reactStrictMode: true,
  // ปิดปุ่ม dev indicator ของ Next (Next 16.4 มี bug ทำให้ console ขึ้น warning ตอนโหลดหน้า)
  devIndicators: false,
};

export default nextConfig;
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | คอมเมนต์พิเศษ บอกชนิดของ object | VS Code เติมคำให้ตอนพิมพ์ตัวเลือก (ไม่มีผลกับการทำงาน) |
| 2 | สร้างตัวแปร `nextConfig` เป็น object ตั้งค่า | เก็บการตั้งค่าทั้งหมด |
| 3-10 | ตั้งค่า Turbopack (ตัว build ของ Next): ไฟล์ที่ลงท้าย `.css` ให้ผ่าน `@tailwindcss/turbopack` ก่อน | ทำให้ class ของ Tailwind/daisyUI ใช้ได้ |
| 11 | เปิดโหมดเข้มงวดของ React | เตือนโค้ดที่อาจมีปัญหาตอนพัฒนา |
| 12-13 | ปิดปุ่มลอยของ Next ที่มุมจอ | Next 16.4 มี bug ทำให้ console ขึ้น warning (กรรมการตรวจว่า console ต้องไม่มี error) |
| 16 | ส่ง nextConfig ออก | Next อ่านค่าจากตรงนี้ |

🧩 **Syntax ที่เจอในไฟล์นี้**

object ซ้อน object (object สอนละเอียดในบท 03 ขั้น 3.6.1)

```syntax
[k:const] [n:nextConfig] [s:=] [s:{]
  [p:turbopack][s::] [s:{]
    [p:rules][s::] [s:{] [s:...] [s:}][s:,]
  [s:}][s:,]
  [p:reactStrictMode][s::] [v:true][s:,]
[s:}][s:;]
```

- ทุก `{` ต้องมี `}` ปิด ย่อหน้าเพิ่ม 2 ช่องทุกครั้งที่เข้าไปข้างในอีกชั้น จะเห็นคู่วงเล็บชัด
- `"*.css"` มี `*` และ `.` ในชื่อ จึงต้องครอบด้วย `" "` (ชื่อปกติอย่าง `rules` ไม่ต้องครอบ)
- `["@tailwindcss/turbopack"]` คือ array (รายการ) ที่มี 1 ค่า
- ชื่อทั้งหมด (`turbopack`, `rules`, `loaders`, `as`, `reactStrictMode`, `devIndicators`) เป็น 🟣 ที่ Next.js กำหนด

> 💡 ไฟล์นี้เป็น **ฉบับแรก** บท 07 จะเพิ่มการส่งต่อ `/api` ไป backend และขนาดไฟล์ที่ส่งต่อได้ ไฟล์ฉบับสมบูรณ์: [frontend/next.config.mjs](../../frontend/next.config.mjs)

### ขั้นที่ 1.7.4 ตั้งค่า globals.css ให้โหลด Tailwind และ daisyUI

> 🎯 **ขั้นนี้จะได้:** ทุกหน้าใช้ class ของ Tailwind และ daisyUI ได้

⌨️ **พิมพ์โค้ด:** เปิด `frontend/styles/globals.css` **ลบของเดิมทั้งหมด** แล้วพิมพ์

```css
@import "tailwindcss";

/* ไม่ใช้ join ของ daisyUI: CSS ของมันใช้ @scope ที่ Turbopack (next dev) ยัง parse ไม่ได้
   และ Tailwind จะสร้าง class นี้เองทุกครั้งที่โค้ดมีคำว่า .join() */
@plugin "daisyui" {
  exclude: join;
}
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | โหลด Tailwind ทั้งหมด | ใช้ class อย่าง `p-4`, `flex`, `text-xl` ได้ |
| 3-4 | คอมเมนต์อธิบายบรรทัด 6 | - |
| 5 | เปิด plugin daisyUI | ใช้ class อย่าง `btn`, `card`, `table`, `modal` ได้ |
| 6 | ยกเว้นส่วน `join` ของ daisyUI | **กัน error 500 ทุกหน้า** ทันทีที่ในโค้ดมีคำว่า `.join(` (ซึ่งเราใช้บ่อย) |

🧩 **Syntax ใหม่: คำสั่งพิเศษใน CSS**

```syntax
[k:@import] [v:"ชื่อ package"][s:;]
[k:@plugin] [v:"ชื่อ plugin"] [s:{]
  [p:ตัวเลือก][s::] [v:ค่า][s:;]
[s:}]
[s:/*] [v:คอมเมนต์ (หลายบรรทัดได้)] [s:*/]
```

- คำสั่งที่ขึ้นต้นด้วย `@` เป็น 🔵 ของ CSS/Tailwind
- ใน `{ }` ของ CSS แต่ละบรรทัดจบด้วย `;` (ไม่ใช่ `,` แบบ JavaScript)
- คอมเมนต์ CSS ใช้ `/* … */` (ใช้ `//` ไม่ได้)

> ❗ **บรรทัด `exclude: join;` ห้ามลืม** ถ้าไม่ใส่ จะเจอ error 500 เรื่อง `@scope` ทุกหน้า

| 4 | ส่งกลับหน้าตา HTML (ในวงเล็บ) | - |
| 5 | `lang="th"` = เว็บภาษาไทย, `data-theme="light"` = ธีมสว่างของ daisyUI | เบราว์เซอร์ตัดคำไทยถูก, หน้าตาไม่เปลี่ยนเป็นธีมมืดตามเครื่อง |

🧩 **Syntax ใหม่: JSX (เขียน HTML ในไฟล์ JavaScript)**

```syntax
[k:export] [k:default] [k:function] [n:ชื่อ][s:()] [s:{]
  [k:return] [s:(]
    [s:<][p:แท็ก] [p:attribute][s:=][v:"ค่า"][s:>]
      [s:<][p:แท็กลูก] [s:/>]
    [s:</][p:แท็ก][s:>]
  [s:);]
[s:}]
```

| รูปแบบ | แปลว่า |
|---|---|
| `function ชื่อ() { … }` | สร้างฟังก์ชันแบบปกติ (อีกแบบนอกจาก `=>` ที่จะเรียนในบท 03) |

| `<Main />` | แท็กที่ไม่มีของข้างใน ปิดในตัวด้วย `/>` **ต้องมี `/` เสมอ** |
| `<body> … </body>` | แท็กที่มีของข้างใน ต้องมีแท็กปิด |
| `className=` | ใน JSX ใช้ `className` แทน `class` ของ HTML |

> 💡 JSX จะสอนละเอียดในบท 07 ตอนนี้แค่รู้ว่า "หน้าตาคล้าย HTML แต่อยู่ในไฟล์ .js"

> 💡 หน้านี้เป็นหน้าทดสอบชั่วคราว บท 07 จะเปลี่ยนให้หน้าแรกพาไปหน้า login ไฟล์ฉบับสมบูรณ์: [frontend/pages/index.js](../../frontend/pages/index.js)

❗ **ถ้าไม่ได้**

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| ปุ่มสีเทาไม่มีสไตล์ | config ผิด หรือ globals.css ไม่ถูกโหลด | ตรวจ `next.config.mjs` (ขั้น 1.7.3), `_app.js` บรรทัด 1 แล้วหยุดและรัน `npm run dev` ใหม่ |
| error 500 เรื่อง `@scope` | ลืม `exclude: join;` | ใส่ใน globals.css ลบโฟลเดอร์ `.next` แล้วรันใหม่ |
| `Module not found: Can't resolve 'daisyui'` | ยังไม่ได้ติดตั้ง หรือติดตั้งผิดโฟลเดอร์ | รันขั้น 1.7.2 ในโฟลเดอร์ frontend |
| `Port 3000 is in use` | มีโปรแกรมใช้ port 3000 | ปิด terminal เก่า (Next จะเสนอ port 3001 แทน แต่ควรใช้ 3000) |

## 1.8 Commit แรก

### ขั้นที่ 1.8.1 ตรวจไฟล์แล้ว commit

> 🎯 **ขั้นนี้จะได้:** ประวัติแรกของโปรเจกต์ใน Git โดยไม่มีไฟล์ลับ

⌨️ **ทำตาม:** กลับไปโฟลเดอร์หลัก

```bash
cd ..
git add .
git status
```

| คำสั่ง | ทำอะไร |
|---|---|
| `git add .` | เลือกทุกไฟล์ที่เปลี่ยน (`.` = ทั้งโฟลเดอร์) เตรียม commit |
| `git status` | ดูว่าเลือกไฟล์อะไรไว้บ้าง |

✅ **ตรวจก่อน commit:** ในรายการ (สีเขียว) **ต้องไม่มี** `.env` และ `node_modules` ถ้ามี แปลว่า `.gitignore` ผิด ให้แก้ก่อน

```bash
git commit -m "Initial project setup"
```

(`-m` = ข้อความบอกว่า commit นี้ทำอะไร นิยมเขียนภาษาอังกฤษสั้นๆ)

✅ **ต้องเห็น:** ข้อความ `[master (root-commit) …] Initial project setup` และจำนวนไฟล์ที่ commit

> ❗ ครั้งแรกถ้าขึ้น `Please tell me who you are` ให้ตั้งชื่อก่อน
> `git config --global user.name "ชื่อทีม"` และ `git config --global user.email "อีเมล"` แล้ว commit ใหม่

## ❗ ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `npm : File ... npm.ps1 cannot be loaded` | PowerShell ไม่อนุญาตให้รันสคริปต์ | รัน `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` หรือเปลี่ยน terminal เป็น Command Prompt |
| `Could not read package.json` | รัน npm ผิดโฟลเดอร์ | `cd backend` หรือ `cd frontend` ก่อน |
| `docker: error during connect` | ยังไม่ได้เปิด Docker Desktop | เปิด Docker Desktop รอจน Engine running |
| `port is already allocated` (3306) | มี MySQL/XAMPP ในเครื่องใช้ port อยู่ | ปิด XAMPP หรือแก้ `DB_PORT=3307` ใน `.env` |
| `yaml: line X` | ย่อหน้า docker-compose.yml ผิด หรือใช้ Tab | ย่อหน้าด้วยช่องว่าง 2 ช่องต่อชั้น |
| เข้า MySQL ไม่ได้ `Access denied` | รหัสใน `.env` ไม่ตรงกับตอนสร้างครั้งแรก | MySQL จำรหัสแรกไว้ ต้องลบข้อมูลแล้วสร้างใหม่: `docker compose down -v` แล้ว `docker compose up -d mysql` (`-v` = ลบ volume ข้อมูลทั้งหมดด้วย) |
| `Unexpected token } in JSON` | package.json มี `,` เกินที่รายการสุดท้าย | ลบ `,` ตัวสุดท้ายออก |
| ปุ่มไม่มีสไตล์ | `globals.css` ไม่ถูก import หรือ config ผิด | ตรวจ `_app.js` และ `next.config.mjs` แล้วรีสตาร์ท `npm run dev` |
| หน้าเว็บ error 500 เรื่อง `@scope` | ลืม `exclude: join` | ใส่ใน `globals.css` แล้วลบโฟลเดอร์ `.next` แล้วรันใหม่ |
| `.env` โผล่ใน `git status` | `.gitignore` สะกดผิด หรือไม่ได้อยู่ที่โฟลเดอร์หลัก | ตรวจชื่อไฟล์ `.gitignore` และที่อยู่ |

> 💡 **`docker compose down` กับ `docker compose down -v` ต่างกันยังไง?**
> `down` = ปิดและลบกล่อง แต่ข้อมูลยังอยู่ใน volume / `down -v` = ลบข้อมูลในฐานข้อมูลทั้งหมดด้วย (ใช้เมื่ออยากเริ่มใหม่หมด)
