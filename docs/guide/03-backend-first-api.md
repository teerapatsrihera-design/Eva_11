# ภาค ก: ความรู้พื้นฐาน (ยังไม่เขียนโค้ด)

## 3.1 API คืออะไร

### ขั้นที่ 3.1.1 เปรียบเทียบกับร้านอาหาร

> 🎯 **ขั้นนี้จะได้:** เข้าใจว่าทำไมหน้าเว็บต้องคุยกับ backend ไม่คุยกับฐานข้อมูลตรงๆ

ลองนึกถึงร้านอาหาร

| ในร้านอาหาร | ในระบบของเรา | ทำหน้าที่ |
|---|---|---|
| ลูกค้า | **Frontend** (หน้าเว็บ) | บอกว่าอยากได้อะไร |
| พนักงานรับออร์เดอร์ | **API** (backend) | รับคำสั่ง ตรวจว่าสั่งได้ไหม แล้วไปบอกครัว |
| ห้องครัว | **ฐานข้อมูล** (MySQL) | เก็บและเตรียมของจริง |
| เมนู | **รายการ endpoint** | บอกว่าสั่งอะไรได้บ้าง |

ลูกค้าเดินเข้าครัวเองไม่ได้ ต้องสั่งผ่านพนักงานเสมอ
เพราะพนักงานต้องตรวจก่อนว่า "สั่งของที่มีในเมนูไหม" และ "จ่ายเงินหรือยัง"

ในระบบของเราก็เหมือนกัน API จะตรวจว่า
1. ข้อมูลที่ส่งมาถูกต้องไหม (เช่น ไม่ได้ส่งชื่อว่างๆ มา)
2. คนที่ขอมีสิทธิ์ไหม (เช่น ครูห้ามลบผู้ใช้คนอื่น)

> 💡 **ทำไมห้ามให้หน้าเว็บต่อ MySQL ตรงๆ?**
> เพราะโค้ดหน้าเว็บทั้งหมดอยู่ในเครื่องของผู้ใช้ ใครก็เปิด DevTools ดูและแก้ได้
> ถ้าใส่รหัสฐานข้อมูลไว้ในหน้าเว็บ ใครก็เอารหัสไปลบข้อมูลทั้งระบบได้
> จึงต้องมี backend เป็นคนกลางคอยตรวจทุกครั้ง

## 3.2 หน้าตาของคำขอและคำตอบ

### ขั้นที่ 3.2.1 คำขอ (Request) มี 3 ส่วน

> 🎯 **ขั้นนี้จะได้:** อ่านคำขอ 1 ครั้งออกว่าแต่ละส่วนคืออะไร

ทุกครั้งที่หน้าเว็บขอข้อมูลจาก API จะส่ง "คำขอ" แบบนี้ไป

```text
POST /api/topics                         ← ส่วนที่ 1: Method + URL
Authorization: Bearer eyJhbGc...         ← ส่วนที่ 2: Header
Content-Type: application/json

{ "title": "ด้านการสอน" }                ← ส่วนที่ 3: Body
```

| ส่วน | เปรียบเหมือน | ตัวอย่างข้างบนแปลว่า |
|---|---|---|
| **Method + URL** | "ทำอะไร" + "กับอะไร" | ขอ **เพิ่ม** (POST) **หัวข้อ** (/api/topics) |
| **Header** | ข้อมูลประกอบ เช่น บัตรผ่าน | แนบบัตรผ่าน (token) และบอกว่า body เป็น JSON |
| **Body** | ของที่ส่งไปด้วย | ชื่อหัวข้อคือ "ด้านการสอน" |

> 💡 คำขอแบบ `GET` (ขอดูข้อมูล) ส่วนใหญ่ **ไม่มี Body** มีแค่ Method + URL + Header

### ขั้นที่ 3.2.2 คำตอบ (Response) ของระบบเรามีรูปแบบเดียว

> 🎯 **ขั้นนี้จะได้:** รู้ว่า API ของเราจะตอบกลับหน้าตาแบบไหนทุกครั้ง

ระบบเรากำหนดว่า **ทุกคำตอบ** ต้องมี 3 ช่องนี้เสมอ (เกณฑ์ 6.8)

```json
{
  "status": "success",
  "message": "เพิ่มหัวข้อสำเร็จ",
  "data": { "id": 3 }
}
```

| ช่อง | ใส่อะไร | ตัวอย่าง |
|---|---|---|
| `status` | สำเร็จหรือไม่ มีแค่ 2 ค่า | `"success"` หรือ `"error"` |
| `message` | ข้อความภาษาไทยไว้โชว์ผู้ใช้ | `"ไม่พบหัวข้อการประเมิน"` |
| `data` | ข้อมูลที่ขอ (ถ้าไม่มีให้เป็น `null`) | รายการหัวข้อ, id ใหม่ |

ตัวอย่างคำตอบตอนผิดพลาด

```json
{
  "status": "error",
  "message": "ไม่พบหัวข้อการประเมิน",
  "data": null
}
```

> 💡 **ทำไมต้องรูปแบบเดียว?** หน้าเว็บจะเขียนโค้ดอ่านผลแบบเดียวได้ทุกหน้า เช่น โชว์ `message` ได้เลยโดยไม่ต้องเดาว่าแต่ละ API ใช้ชื่อช่องอะไร

## 3.3 HTTP Method: บอกว่า "ทำอะไร"

### ขั้นที่ 3.3.1 จำ Method 4 ตัว

> 🎯 **ขั้นนี้จะได้:** เลือก Method ได้ถูกว่างานไหนใช้ตัวไหน

| Method | แปลว่า | ตรงกับ SQL | ตัวอย่าง |
|---|---|---|---|
| `GET` | ขอดู | `SELECT` | `GET /api/topics` = ขอดูหัวข้อทั้งหมด |
| `POST` | เพิ่มใหม่ | `INSERT` | `POST /api/topics` = เพิ่มหัวข้อใหม่ |
| `PUT` | แก้ไข | `UPDATE` | `PUT /api/topics/3` = แก้หัวข้อ id 3 |
| `DELETE` | ลบ | `DELETE` | `DELETE /api/topics/3` = ลบหัวข้อ id 3 |

> 💡 **วิธีจำ:** 4 ตัวนี้เรียกรวมกันว่า **CRUD** = **C**reate (POST), **R**ead (GET), **U**pdate (PUT), **D**elete (DELETE)
> ตัวอย่าง: ครูกดปุ่ม "บันทึกคะแนนที่แก้" = แก้ของที่มีอยู่แล้ว จึงใช้ `PUT` แต่ถ้าบันทึกครั้งแรก = เพิ่มใหม่ ใช้ `POST`

## 3.4 Status Code: บอกว่า "ผลเป็นอย่างไร"

### ขั้นที่ 3.4.1 จำ Status Code 7 ตัว

> 🎯 **ขั้นนี้จะได้:** เลือกตัวเลขตอบกลับได้ถูก (กรรมการตรวจข้อนี้)

Status Code คือตัวเลข 3 หลักที่ส่งกลับไปพร้อมคำตอบ บอกผลแบบสั้นๆ

| Code | แปลว่า | ใช้เมื่อ |
|---|---|---|
| **200** | สำเร็จ | ดู / แก้ / ลบ สำเร็จ |
| **201** | สร้างสำเร็จ | `POST` เพิ่มข้อมูลใหม่สำเร็จ |
| **400** | ข้อมูลผิด | ไม่กรอกช่องบังคับ, รูปแบบผิด, ข้อมูลซ้ำ |
| **401** | ยังไม่ได้ login | ไม่มีบัตรผ่าน (token) หรือบัตรปลอม |
| **403** | ไม่มีสิทธิ์ | login แล้ว แต่บทบาทนี้ทำเรื่องนี้ไม่ได้ |
| **404** | ไม่พบ | ขอ id ที่ไม่มีอยู่จริง |
| **500** | ระบบพัง | error ที่ไม่คาดคิด เช่น ฐานข้อมูลดับ |

> 💡 **วิธีจำแบบกลุ่ม:** ขึ้นต้นด้วย **2** = ดี, **4** = ผู้ใช้ทำผิด, **5** = server ผิด

> 💡 **401 กับ 403 ต่างกันยังไง? (กรรมการถามบ่อย)**
> เปรียบกับการเข้าห้องสมุด
> - **401** = ไม่มีบัตรห้องสมุดเลย ยามไม่รู้ว่าเราเป็นใคร
> - **403** = มีบัตร ยามรู้ว่าเราเป็นใคร แต่บัตรนักเรียนเข้าห้องครูไม่ได้

> 💡 **ขอ id ที่ไม่มี ตอบ 400 หรือ 404?** ตอบ **404** เพราะคำขอเขียนถูกรูปแบบแล้ว แค่ข้อมูลไม่มีอยู่จริง

## 3.5 RESTful: ตั้งชื่อ URL ให้ถูกหลัก

### ขั้นที่ 3.5.1 กฎตั้งชื่อ URL 5 ข้อ

> 🎯 **ขั้นนี้จะได้:** ตั้งชื่อ URL ตามหลัก RESTful (เกณฑ์ 4.1, 4.2)

RESTful คือ "ธรรมเนียม" การตั้ง URL ที่โปรแกรมเมอร์ทั่วโลกใช้ หลักใหญ่คือ **URL บอก "ของ" ส่วน Method บอก "การกระทำ"**

| กฎ | ✅ ถูก | ❌ ผิด |
|---|---|---|
| 1. ใช้คำนาม พหูพจน์ (เติม s) | `/api/topics` | `/api/getTopics` |
| 2. ข้อมูล 1 รายการ ต่อท้ายด้วย id | `/api/topics/3` | `/api/topic?id=3` |
| 3. การกระทำบอกด้วย Method ไม่ใส่ใน URL | `DELETE /api/topics/3` | `POST /api/deleteTopic` |
| 4. ข้อมูลย่อยของอีกอย่าง ใช้ path ซ้อน | `/api/self-evaluations/1/evidences` | `/api/addEvidence` |
| 5. ชื่อหลายคำ คั่นด้วยขีด `-` | `/api/self-evaluations` | `/api/selfEvaluations` |

> 💡 ตัวอย่าง: `/api/editUser/5` ผิดกฎข้อ 1 และ 3 (มีคำกริยา edit ใน URL และไม่เป็นพหูพจน์) ที่ถูกคือ `PUT /api/users/5`

# ภาค ข: เขียนโค้ดทีละขั้น

## 3.6 วิธีอ่านโค้ด และไฟล์แรก

### ขั้นที่ 3.6.0 รู้จักคำ 5 ชนิดในโค้ด

> 🎯 **ขั้นนี้จะได้:** แยกได้ว่าคำแต่ละคำในโค้ด "ต้องพิมพ์ตามเป๊ะ" หรือ "ตั้งเองได้"

โค้ด 1 บรรทัดประกอบด้วยคำหลายชนิด คู่มือนี้แยกสีให้ทุกครั้งที่สอน syntax ใหม่

| สี | ชนิด | ความหมาย | ตัวอย่าง |
|---|---|---|---|
| 🔵 | **syntax (คำสงวน)** | คำที่ภาษา JavaScript กำหนด **ต้องพิมพ์ตามนี้ทุกตัวอักษร** ห้ามแปลง | `import` `from` `const` `async` `await` `return` `if` |
| 🟢 | **ชื่อที่ตั้งเอง** | เราตั้งชื่ออะไรก็ได้ แต่ต้องใช้ชื่อเดิมทุกครั้งที่เรียก | `pool` `rows` `topics` |
| 🟣 | **ชื่อที่ package / ระบบกำหนด** | ชื่อที่คนสร้าง package ตั้งไว้ **ต้องสะกดตามเขา** | `express` `createPool` `query` `json` `process.env` |
| 🟠 | **ค่า / ข้อมูล** | ข้อความใน `" "`, ตัวเลข, `true` `false` `null` | `"สำเร็จ"` `200` `true` |
| ⚪ | **เครื่องหมาย** | วงเล็บ จุด จุลภาค ฯลฯ **วงเล็บเปิดต้องมีปิดเสมอ** | `( )` `{ }` `[ ]` `.` `,` `;` `=>` |

ตัวอย่างการแยกสี

```syntax
[k:const] [n:pool] [s:=] [p:mysql][s:.][p:createPool][s:(][s:{] [s:...] [s:}][s:)][s:;]
```

> 💡 **ทำไมต้องแยก?** มือใหม่มักงงว่า "ต้องพิมพ์ `pool` เป๊ะๆ ไหม" คำตอบคือไม่ต้อง (🟢 ตั้งเอง จะตั้งว่า `db` ก็ได้) แต่ `createPool` ต้องพิมพ์ตามเป๊ะ (🟣 mysql2 ตั้งไว้) ถ้าพิมพ์ `createpool` (p เล็ก) จะ error ทันที

> ❗ **JavaScript แยกตัวพิมพ์เล็กใหญ่**: `Router` กับ `router` คือคนละชื่อกัน

**วิธีอ่านแต่ละขั้นในภาคนี้**

| สัญลักษณ์ | ส่วนนี้คืออะไร |
|---|---|
| ⌨️ พิมพ์โค้ด | โค้ดที่ต้องพิมพ์ มีเลขบรรทัดด้านซ้าย (**ไม่ต้องพิมพ์เลขบรรทัด**) |
| 🔍 อ่านโค้ดทีละบรรทัด | ตาราง 3 ช่อง: บรรทัดนี้ **ทำอะไร** และ **เอาไว้ใช้ทำอะไรในระบบ** |
| 🧩 Syntax | โครงสร้างของ syntax ใหม่ที่เจอในขั้นนั้น แยกสีทีละคำ + กฎที่ต้องจำ |
| ✅ ลองเลย | รันแล้วต้องเห็นอะไร **ไม่เห็นห้ามไปขั้นต่อไป** |
| ❗ ถ้าไม่ได้ | ข้อความ error ที่เจอบ่อย และวิธีแก้ |

> 💡 **กติกาของภาคนี้**
> 1. **พิมพ์เอง อย่าคัดลอก** การพิมพ์เองทำให้จำได้ วันแข่งไม่มีให้คัดลอก
> 2. **ทุกขั้นต้องเห็นผล ✅ ก่อนไปขั้นต่อไป**
> 3. syntax ที่สอนไปแล้ว จะไม่อธิบายซ้ำ แต่จะบอกว่าสอนไว้ขั้นไหน กลับไปดูได้

### ขั้นที่ 3.6.1 สร้างไฟล์ env.js (โหลดค่าตั้งค่าจาก .env)

> 🎯 **ขั้นนี้จะได้:** ไฟล์ที่อ่านค่ารหัสฐานข้อมูลจาก `.env` มาให้โค้ดใช้

📖 **รู้ก่อนพิมพ์**
ในบท 01 เราเก็บค่าตั้งค่า (เช่น รหัสผ่านฐานข้อมูล) ไว้ในไฟล์ `.env` ที่โฟลเดอร์หลักของโปรเจกต์
แต่ Node.js ไม่อ่านไฟล์นี้ให้เอง ต้องใช้ package ชื่อ `dotenv` ช่วยโหลด

```text
Eva_Learn/
├── .env            ← ไฟล์ที่ต้องการอ่าน (อยู่ชั้นนอก)
└── backend/
    └── env.js      ← ไฟล์ที่กำลังจะเขียน (อยู่ชั้นใน)
```

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `backend/env.js`

```js
import dotenv from "dotenv";
import path from "node:path";

// โหลด .env จากรากโปรเจกต์ (ไฟล์เดียวกับที่ docker-compose ใช้)
dotenv.config({ path: path.join(import.meta.dirname, "..", ".env"), quiet: true });
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | ดึง package `dotenv` เข้ามาในไฟล์ ตั้งชื่อว่า `dotenv` | ใช้สั่งโหลดไฟล์ .env ในบรรทัด 5 |
| 2 | ดึงเครื่องมือจัดการ path ของไฟล์ (มากับ Node.js ไม่ต้อง npm install) | ใช้ประกอบที่อยู่ไฟล์ .env ให้ถูกต้องทั้งบน Windows และ Linux |
| 3 | บรรทัดว่าง | เว้นให้อ่านง่าย แยกส่วน import กับส่วนทำงาน |
| 4 | คอมเมนต์ คอมพิวเตอร์ไม่อ่าน | อธิบายให้คนอ่านโค้ดรู้ว่าบรรทัดถัดไปทำอะไร |
| 5 | สั่งให้ dotenv โหลดไฟล์ `.env` จากที่อยู่ที่บอก | หลังบรรทัดนี้ ทุกไฟล์ใช้ค่าใน .env ได้ผ่าน `process.env.ชื่อ` เช่น `process.env.DB_HOST` |

| `quiet: true` | - | ไม่ต้องพิมพ์ข้อความแจ้งตอนโหลด terminal จะได้ไม่รก |

🧩 **Syntax ใหม่ 1: `import` (ดึงของจากที่อื่นมาใช้)**

โครงสร้าง

```syntax

```

เทียบกับบรรทัด 1

```syntax

```

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `import` | 🔵 syntax | บอกว่า "จะดึงของเข้ามา" |
| `dotenv` (ตัวแรก) | 🟢 ตั้งเอง | ชื่อที่ใช้เรียกในไฟล์นี้ ตั้งเป็น `abc` ก็ได้ แต่ตั้งตามชื่อ package จะจำง่าย |
| `from` | 🔵 syntax | แปลว่า "จาก" |
| `"dotenv"` | 🟠 ค่า (ข้อความ) | บอกที่มา ต้องตรงกับชื่อที่ `npm install` |
| `;` | ⚪ เครื่องหมาย | จบคำสั่ง |

กฎที่ต้องจำ
- `import` ต้องอยู่ **บนสุดของไฟล์** ก่อนโค้ดอื่น
- ที่มาต้องอยู่ใน `" "` เสมอ
- ที่มาเป็นชื่อ package → เขียนชื่อเฉยๆ เช่น `"express"` (ไปหาใน `node_modules`)
- ที่มาเป็นไฟล์ของเราเอง → ขึ้นต้นด้วย `./` (โฟลเดอร์เดียวกัน) หรือ `../` (ขึ้นไป 1 ชั้น) และ **ต้องมี `.js` ต่อท้าย** เช่น `"./db.js"`
- ที่มาขึ้นต้นด้วย `node:` → ของที่มากับ Node.js เช่น `"node:path"`

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `dotenv` | 🟢 ตั้งเอง | ชื่อที่ตั้งไว้ตอน import ในบรรทัด 1 |

- ส่งหลายค่า คั่นด้วย `,` เช่น `path.join(ก, ข, ค)`


| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `{ }` | ⚪ เครื่องหมาย | เปิด-ปิด object |
| `path`, `quiet` | 🟣 package กำหนด | ชื่อช่องที่ dotenv รู้จัก (ต้องสะกดตามเอกสารของ dotenv) |

> 💡 ชื่อช่องใน object เป็น 🟣 หรือ 🟢 ขึ้นอยู่กับ "ใครเป็นคนอ่าน" ถ้าส่งให้ package อ่าน (แบบนี้) ต้องใช้ชื่อที่ package กำหนด ถ้าเราสร้างใช้เอง ตั้งชื่อเองได้

## 3.7 เชื่อมฐานข้อมูล

### ขั้นที่ 3.7.1 Pool คืออะไร

> 🎯 **ขั้นนี้จะได้:** เข้าใจว่าทำไมเราใช้ "pool" ในการต่อฐานข้อมูล

📖 การเปิดสายเชื่อมต่อฐานข้อมูลใหม่ 1 ครั้ง ใช้เวลานาน (เหมือนโทรศัพท์ต้องรอสายต่อติด)
ถ้าเปิดใหม่ทุกครั้งที่มีคนเรียก API ระบบจะช้ามาก

**Pool** = เปิดสายค้างไว้หลายเส้น ใครจะใช้ก็หยิบไป ใช้เสร็จก็คืน

```text
  คำขอ A ──▶ ┌────────── pool ──────────┐
  คำขอ B ──▶ │  สาย 1  สาย 2  สาย 3 ...  │ ──▶ MySQL
  คำขอ C ──▶ └──────────────────────────┘
```

ไม่ต้องพิมพ์อะไรในขั้นนี้ แค่เข้าใจไว้ เพราะต่อไปเราจะเรียกใช้ `pool` ทุกครั้งที่คุยกับฐานข้อมูล

### ขั้นที่ 3.7.2 สร้างไฟล์ db.js

> 🎯 **ขั้นนี้จะได้:** ตัวแปร `pool` ที่ไฟล์อื่น import ไปใช้คุยกับ MySQL ได้

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `backend/db.js`

```js
import "./env.js";
import mysql from "mysql2/promise";

// pool เดียวใช้ทั้งระบบ
const pool = mysql.createPool({
  host: process.env.DB_HOST,
  port: process.env.DB_PORT,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME,
});

export default pool;
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | รันไฟล์ env.js (ไม่ได้เอาชื่ออะไรมา) | ให้ค่าใน .env ถูกโหลดก่อน บรรทัด 6-10 จะได้อ่าน `process.env` ได้ |
| 2 | ดึง mysql2 แบบ `promise` | แบบ promise ใช้คู่กับ `await` ได้ (รอผลจากฐานข้อมูลแบบอ่านง่าย) |
| 4 | คอมเมนต์ | เตือนว่าทั้งระบบใช้ pool นี้ตัวเดียว ห้ามสร้างใหม่ในไฟล์อื่น |
| 5 | สร้าง pool แล้วเก็บไว้ในชื่อ `pool` | เป็น "ทางเข้าฐานข้อมูล" ที่ทุก API จะใช้ |
| 6 | บอกที่อยู่เครื่องฐานข้อมูล (`localhost`) | ให้ pool รู้ว่าต้องไปต่อที่เครื่องไหน |
| 7 | บอก port (`3306`) | ช่องทางที่ MySQL รอรับ |
| 8-9 | บอกชื่อผู้ใช้และรหัสผ่าน MySQL | ใช้ยืนยันตัวตนกับ MySQL |
| 10 | บอกชื่อฐานข้อมูล (`eva`) | ให้ SQL ทุกคำสั่งทำงานในฐานข้อมูลนี้ ไม่ต้องเขียนชื่อซ้ำ |
| 11 | ปิดวงเล็บ object `}` และวงเล็บคำสั่ง `)` | จบคำสั่ง createPool |
| 13 | ส่ง `pool` ออกจากไฟล์ | ให้ไฟล์อื่น (app.js, routes) import ไปใช้ได้ |

- ใช้กับไฟล์ที่ทำงานเสร็จในตัว เช่น env.js ที่แค่โหลด .env

### ขั้นที่ 3.7.3 ทดสอบว่าต่อฐานข้อมูลติด

> 🎯 **ขั้นนี้จะได้:** มั่นใจว่า db.js ใช้ได้จริง ก่อนเขียนต่อ

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ทดลอง `backend/try-db.js` (ใช้เสร็จแล้วจะลบทิ้ง)

```js
import pool from "./db.js";

const [rows] = await pool.query("SELECT id, username, role FROM users");
console.log(rows);
process.exit();
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | ดึง `pool` จาก db.js | เพื่อทดสอบว่า db.js ที่เพิ่งเขียนใช้ได้ |
| 3 | ส่ง SQL ไปที่ MySQL **รอ** จนได้ผล แล้วเก็บแถวที่ได้ไว้ใน `rows` | เป็นการคุยกับฐานข้อมูลครั้งแรก ถ้าบรรทัดนี้ผ่าน แปลว่าต่อติด |
| 4 | พิมพ์ค่าใน `rows` ออกที่ terminal | ให้เราเห็นด้วยตาว่าได้ข้อมูลอะไร |
| 5 | สั่งจบโปรแกรม | ถ้าไม่สั่ง pool จะเปิดสายค้างไว้ โปรแกรมจะไม่จบเอง |

🧩 **Syntax ใหม่ 1: `await` (รอให้เสร็จก่อน)**

โครงสร้าง

```syntax
[k:const] [n:ผลลัพธ์] [s:=] [k:await] [n:งานที่ต้องใช้เวลา][s:;]
```

- การถามฐานข้อมูลต้องใช้เวลา `await` = "หยุดรอตรงนี้จนได้คำตอบ แล้วค่อยทำบรรทัดต่อไป"
- ถ้าลืม `await` ตัวแปรจะได้ "ใบสัญญาว่าจะตอบ" (เรียกว่า Promise) แทนข้อมูลจริง
- ใช้ `await` ได้ 2 ที่: บนสุดของไฟล์ (แบบไฟล์นี้) หรือในฟังก์ชันที่มี `async` (สอนในขั้น 3.9.3)

🧩 **Syntax ใหม่ 2: `const [ชื่อ] = …` (แกะช่องแรกของ array)**

**array** คือรายการหลายค่าเรียงกัน เขียนใน `[ ]` เช่น `[10, 20, 30]`

`pool.query()` ตอบกลับมาเป็น array 2 ช่อง: `[แถวข้อมูล, ข้อมูลคอลัมน์]` เราอยากได้แค่ช่องแรก

โครงสร้าง

```syntax
[k:const] [s:\[][n:ชื่อสำหรับช่องแรก][s:\]] [s:=] [v:array][s:;]
```

เทียบกับบรรทัด 3

```syntax
[k:const] [s:\[][n:rows][s:\]] [s:=] [k:await] [n:pool][s:.][p:query][s:(][v:"SELECT ..."][s:)][s:;]
```

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `[rows]` | ⚪ + 🟢 | วงเล็บเหลี่ยมฝั่งซ้ายของ `=` แปลว่า "แกะ array" เอาช่องแรกมาใส่ชื่อ `rows` |

| `query` | 🟣 package กำหนด | คำสั่งส่ง SQL ของ mysql2 |
| `"SELECT ..."` | 🟠 ค่า | คำสั่ง SQL เป็นข้อความ ต้องอยู่ใน `" "` |

ตัวอย่างเทียบให้เห็นภาพ

```js
const [a] = [10, 20];    // a = 10 (เอาช่องแรก)
const [x, y] = [10, 20]; // x = 10, y = 20 (เอา 2 ช่อง)
```

### ขั้นที่ 3.7.5 ส่งค่าเข้า SQL อย่างปลอดภัย (ใช้ `?`)

> 🎯 **ขั้นนี้จะได้:** เขียน SQL ที่มีค่าจากผู้ใช้ โดยไม่โดนแฮก (SQL Injection)

📖 สมมติอยากดึงผู้ใช้ตาม id ที่หน้าเว็บส่งมา ถ้าเอาค่าจากผู้ใช้ไปต่อเป็นข้อความ SQL ตรงๆ

```text
ผู้ใช้ส่ง id มาเป็น:   1 OR 1=1
SQL ที่ได้:            SELECT * FROM users WHERE id = 1 OR 1=1
```

`1=1` เป็นจริงเสมอ จึงได้ข้อมูล **ทุกแถว** ออกไป นี่คือ **SQL Injection** (แฮกด้วยการแทรกคำสั่ง SQL)

✅ **วิธีที่ถูก:** ใส่ `?` ในตำแหน่งที่จะมีค่า แล้วส่งค่าจริงเป็น array ตามมา

```js
pool.query("SELECT * FROM users WHERE id = ?", [id]);
pool.query("SELECT * FROM users WHERE role = ? AND department = ?", [role, dept]);
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | ดึงผู้ใช้ที่ id ตรงกับค่า `id` | แบบที่ใช้บ่อยที่สุด: ดู / แก้ / ลบ ข้อมูล 1 รายการ |
| 2 | มี `?` 2 ตัว ค่าใน array 2 ตัว เรียงตามลำดับ | ค้นหาด้วยหลายเงื่อนไข |

🧩 **Syntax ใหม่: query แบบมี `?`**

โครงสร้าง

```syntax
[n:pool][s:.][p:query][s:(][v:"SQL ที่มี ? ตรงตำแหน่งค่า"][s:,] [s:\[][n:ค่าแทน?ตัวที่1][s:,] [n:ค่าแทน?ตัวที่2][s:\]][s:)]
```

กฎที่ต้องจำ
- จำนวน `?` ต้อง **เท่ากับ** จำนวนค่าใน `[ ]`
- ค่าใน `[ ]` เรียง **ตามลำดับ** ของ `?` จากซ้ายไปขวา
- ใช้ `?` แทน **ค่า** ได้เท่านั้น (เช่น id, ชื่อ) ใช้แทนชื่อตารางหรือชื่อคอลัมน์ไม่ได้
- mysql2 จะครอบค่าให้ปลอดภัยเอง `1 OR 1=1` จะกลายเป็นข้อความธรรมดา ไม่ใช่คำสั่ง

> ❗ **จำให้ขึ้นใจ: ค่าที่มาจากผู้ใช้ ต้องผ่าน `?` เสมอ ห้ามต่อข้อความใส่ SQL**

## 3.8 ฟังก์ชันตอบกลับรูปแบบเดียว

### ขั้นที่ 3.8.1 ฟังก์ชัน ok (ตอบตอนสำเร็จ)

> 🎯 **ขั้นนี้จะได้:** ฟังก์ชันที่ตอบ `{ status: "success", message, data }` ให้อัตโนมัติ

📖 **ทำไมต้องมี?** ถ้าทุก API เขียนคำตอบเอง สักวันจะมีคนพิมพ์ `staus` ผิด หรือลืม `message`
เราเลยเขียนฟังก์ชันกลางไว้ 2 ตัว ใช้ทั้งระบบ รูปแบบจะเหมือนกันทุกครั้งแน่นอน (เกณฑ์ 6.8)

📖 **ฟังก์ชันคืออะไร?** คือ "ชุดคำสั่งที่ตั้งชื่อไว้" เรียกใช้ซ้ำได้ เหมือนสูตรอาหาร เขียนสูตรครั้งเดียว ทำกี่จานก็ได้ แค่ใส่วัตถุดิบ (ค่า) ต่างกัน

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `backend/utils/response.js`

```js
// รูปแบบ response เดียวทั้งระบบ: { status, message, data }
export const ok = (res, data = null, message = "สำเร็จ", code = 200) =>
  res.status(code).json({ status: "success", message, data });
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | คอมเมนต์ | บอกว่าไฟล์นี้คุมรูปแบบคำตอบทั้งระบบ |
| 2 | สร้างฟังก์ชันชื่อ `ok` รับค่า 4 ตัว และส่งออกจากไฟล์ | ให้ทุก route เรียก `ok(...)` ตอนทำงานสำเร็จ |
| 3 | ตั้ง status code แล้วตอบเป็น JSON 3 ช่อง | สิ่งที่หน้าเว็บจะได้รับจริง |

ค่าที่ฟังก์ชันรับ (เรียกว่า **พารามิเตอร์**)

| ตัวที่ | ชื่อ | เอาไว้ทำอะไร | ถ้าไม่ส่งมา ใช้ค่า |
|---|---|---|---|
| 1 | `res` | ตัวช่วยตอบกลับที่ Express ให้มา | (ต้องส่งเสมอ) |
| 2 | `data` | ข้อมูลที่จะส่งกลับ เช่น รายการหัวข้อ | `null` |
| 3 | `message` | ข้อความโชว์ผู้ใช้ | `"สำเร็จ"` |
| 4 | `code` | status code | `200` |

🧩 **Syntax ใหม่ 1: Arrow function `=>` (สร้างฟังก์ชัน)**

โครงสร้าง (แบบคำสั่งเดียว)

```syntax
[k:const] [n:ชื่อฟังก์ชัน] [s:=] [s:(][n:พารามิเตอร์1][s:,] [n:พารามิเตอร์2][s:)] [s:=>] [v:ค่าที่ส่งกลับ][s:;]
```

ตัวอย่างง่ายๆ ก่อน

```syntax
[k:const] [n:add] [s:=] [s:(][n:a][s:,] [n:b][s:)] [s:=>] [n:a] [s:+] [n:b][s:;]
```

เรียกใช้ `add(2, 3)` จะได้ `5` (`a` = 2, `b` = 3)

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `add` | 🟢 ตั้งเอง | ชื่อฟังก์ชัน ใช้ตอนเรียก |
| `(a, b)` | ⚪ + 🟢 | ช่องรับค่า ตั้งชื่อเอง ใช้ได้เฉพาะในฟังก์ชันนี้ |
| `=>` | ⚪ เครื่องหมาย | ลูกศร แปลว่า "แล้วทำ..." (พิมพ์ `=` ตามด้วย `>` ติดกัน) |
| `a + b` | - | สิ่งที่ส่งกลับ |

กฎที่ต้องจำ
- หลัง `=>` ถ้าเป็นคำสั่ง **เดียว** ไม่ต้องใส่ `{ }` ผลของคำสั่งนั้นจะถูกส่งกลับเอง
- ถ้าหลายคำสั่ง ต้องใส่ `{ }` (สอนในขั้น 3.9.1)
- ขึ้นบรรทัดใหม่หลัง `=>` ได้ (แบบบรรทัด 2-3 ของเรา) ย่อหน้าบรรทัดถัดไปเพื่อให้รู้ว่าเป็นส่วนเดียวกัน

🧩 **Syntax ใหม่ 2: ค่าเริ่มต้นของพารามิเตอร์**

```syntax
[s:(][n:ชื่อพารามิเตอร์] [s:=] [v:ค่าที่ใช้ถ้าไม่ได้ส่งมา][s:)]
```

- `data = null` แปลว่า "ถ้าคนเรียกไม่ส่ง data มา ให้ data เป็น null"
- เอาไว้ทำให้เรียกสั้นลง เช่น `ok(res, rows)` ไม่ต้องส่ง message และ code ก็ได้

🧩 **Syntax ใหม่ 3: `export const` (ส่งออกแบบมีชื่อ)**

```syntax
[k:export] [k:const] [n:ชื่อ] [s:=] [v:ค่า][s:;]
```

ไฟล์อื่นรับไปใช้ด้วย

```syntax
[k:import] [s:{] [n:ชื่อ] [s:}] [k:from] [v:"./ไฟล์.js"][s:;]
```

| | `export default` (ขั้น 3.7.2) | `export const` |
|---|---|---|
| 1 ไฟล์มีได้ | 1 ตัว | หลายตัว |
| ตอน import | ไม่มี `{ }` ตั้งชื่อใหม่ได้ | ต้องมี `{ }` และ **ใช้ชื่อตรงกับตอน export** |

🧩 **Syntax ใหม่ 4: เรียกคำสั่งต่อกันเป็นทอด (method chaining)**

```syntax
[n:res][s:.][p:status][s:(][n:code][s:)][s:.][p:json][s:(][v:{ ... }][s:)]
```

- อ่านจากซ้ายไปขวา: "ตั้ง status เป็น code **แล้ว** ตอบเป็น JSON"
- ทำได้เพราะ `res.status()` ส่ง `res` กลับมาให้ เลยเรียก `.json()` ต่อได้เลย
- `status` และ `json` เป็น 🟣 คำสั่งที่ Express มีให้

🧩 **Syntax ใหม่ 5: object แบบย่อชื่อ**

ถ้า **ชื่อช่อง** กับ **ชื่อตัวแปร** เหมือนกัน เขียนชื่อเดียวได้

```syntax
[s:{] [n:message][s:,] [n:data] [s:}]
```

เหมือนกับ

```syntax
[s:{] [n:message][s::] [n:message][s:,] [n:data][s::] [n:data] [s:}]
```

ในบรรทัด 3 `{ status: "success", message, data }` = ช่อง status ใส่ค่า `"success"` ส่วน message และ data ใช้ค่าจากพารามิเตอร์ชื่อเดียวกัน

### ขั้นที่ 3.8.2 ฟังก์ชัน fail (ตอบตอนผิดพลาด)

> 🎯 **ขั้นนี้จะได้:** ฟังก์ชันที่ตอบ `{ status: "error", message, data }`

⌨️ **พิมพ์โค้ด:** เพิ่มต่อท้ายไฟล์ `backend/utils/response.js`

```js
export const fail = (res, code, message, data = null) =>
  res.status(code).json({ status: "error", message, data });
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | สร้างฟังก์ชัน `fail` รับค่า 4 ตัว ส่งออกจากไฟล์ | ให้ทุก route เรียกตอนเจอปัญหา เช่น ไม่พบข้อมูล, ข้อมูลผิด |
| 2 | ตั้ง status code แล้วตอบ JSON โดย status เป็น `"error"` | หน้าเว็บดู `status` แล้วรู้ทันทีว่าต้องโชว์กล่องแจ้ง error |

syntax ทั้งหมดเหมือนขั้น 3.8.1 ต่างกันแค่

| | `ok` | `fail` |
|---|---|---|
| `status` | `"success"` | `"error"` |
| ลำดับพารามิเตอร์ | `res, data, message, code` | `res, code, message, data` |
| ทำไมลำดับต่างกัน | ตอนสำเร็จ ส่วนใหญ่ส่งแค่ data | ตอนผิด ต้องบอก code กับข้อความเสมอ จึงเอาไว้ข้างหน้า |

**ตัวอย่างการเรียกใช้ (จะได้ใช้จริงในขั้นต่อๆ ไป)**

```js
ok(res, rows);                               // 200 { status: "success", message: "สำเร็จ", data: rows }
ok(res, { id: 3 }, "เพิ่มหัวข้อสำเร็จ", 201);  // 201 พร้อม id ใหม่
fail(res, 404, "ไม่พบหัวข้อการประเมิน");       // 404 { status: "error", message: "...", data: null }
fail(res, 400, "กรุณากรอกชื่อ");               // 400
```

✅ **ลองเลย:** ยังรันดูผลไม่ได้ จะได้เห็นผลในขั้น 3.9.1

## 3.9 สร้าง Express server

### ขั้นที่ 3.9.1 server ตัวแรก ตอบ "สวัสดี"

> 🎯 **ขั้นนี้จะได้:** เปิดเบราว์เซอร์แล้วเห็น JSON จาก server ของเราเอง

📖 **Express** คือ package ที่ช่วยสร้าง API ได้ง่าย เราบอกแค่ว่า "ถ้ามีคำขอ Method นี้ URL นี้ ให้ทำอะไร"

เราจะแยกเป็น 2 ไฟล์
- `app.js` = กำหนดว่า URL ไหนทำอะไร
- `server.js` = เปิด port 5000 รอรับคำขอ

(เหตุผลที่แยก: ตอนเขียน test ในบท 12 เราจะดึง `app` ไปทดสอบโดยไม่ต้องเปิด port)

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `backend/app.js`

```js
import "./env.js";
import express from "express";
import { ok, fail } from "./utils/response.js";

const app = express();

app.get("/api/hello", (req, res) => {
  ok(res, { name: "Eva" }, "สวัสดี");
});

export default app;
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | โหลด .env | ให้ทุกค่าตั้งค่าพร้อมก่อนเริ่ม |
| 2 | ดึง package express | ใช้สร้าง app ในบรรทัด 5 |
| 3 | ดึงฟังก์ชัน `ok` และ `fail` จากขั้น 3.8 | ใช้ตอบกลับรูปแบบเดียวกันทุก route |
| 5 | สร้าง app ของ Express เก็บไว้ในชื่อ `app` | `app` คือตัวกลางที่เราจะผูก URL ต่างๆ เข้าไป |
| 7 | ผูก URL: ถ้ามีคำขอ **GET** มาที่ **/api/hello** ให้ทำฟังก์ชันที่ส่งให้ | นี่คือการสร้าง "endpoint" 1 ตัว |
| 8 | ตอบกลับด้วย `ok` ข้อมูล `{ name: "Eva" }` ข้อความ "สวัสดี" | เพื่อทดสอบว่า server ทำงาน |
| 9 | ปิด `}` ของฟังก์ชัน และ `)` ของ `app.get(` | จบการผูก URL |
| 11 | ส่ง app ออกจากไฟล์ | ให้ server.js เอาไปเปิด port |

🧩 **Syntax ใหม่ 1: import แบบมีชื่อ `{ }`**

```syntax
[k:import] [s:{] [n:ok][s:,] [n:fail] [s:}] [k:from] [v:"./utils/response.js"][s:;]
```

- ใช้รับของที่ไฟล์นั้น `export const` ไว้ (ขั้น 3.8.1)
- ชื่อใน `{ }` ต้อง **ตรงกับชื่อตอน export** (สะกดผิด = error)
- ดึงหลายตัวพร้อมกัน คั่นด้วย `,`

🧩 **Syntax ใหม่ 2: ผูก URL กับฟังก์ชัน (route) ⭐ สำคัญที่สุดของ backend**

โครงสร้าง

```syntax
[n:app][s:.][p:method][s:(][v:"/URL"][s:,] [s:(][n:req][s:,] [n:res][s:)] [s:=>] [s:{]
  [v:คำสั่งที่จะทำเมื่อมีคำขอเข้ามา (กี่บรรทัดก็ได้)]
[s:}][s:)][s:;]
```

เทียบกับบรรทัด 7-9

```syntax
[n:app][s:.][p:get][s:(][v:"/api/hello"][s:,] [s:(][n:req][s:,] [n:res][s:)] [s:=>] [s:{]
  [n:ok][s:(][n:res][s:,] [v:{ name: "Eva" }][s:,] [v:"สวัสดี"][s:)][s:;]
[s:}][s:)][s:;]
```

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `app` | 🟢 ตั้งเอง | ชื่อที่สร้างในบรรทัด 5 |
| `get` | 🟣 Express กำหนด | Method ที่จะรับ ใช้ได้ 4 แบบ: `get` `post` `put` `delete` (ตัวเล็ก) |
| `"/api/hello"` | 🟠 ค่า | URL ที่จะรับ |
| `(req, res) => { … }` | ฟังก์ชัน | งานที่จะทำเมื่อมีคำขอเข้ามา (เรียกว่า **handler**) |
| `req` | 🟢 ตั้งเอง (แต่ทุกคนใช้ชื่อนี้) | **คำขอ** ที่เข้ามา เช่น อยากรู้ body ดูที่ `req.body` |
| `res` | 🟢 ตั้งเอง (แต่ทุกคนใช้ชื่อนี้) | **ตัวช่วยตอบกลับ** ส่งให้ `ok(res, …)` |
| `{ }` หลัง `=>` | ⚪ เครื่องหมาย | ครอบคำสั่งหลายบรรทัดของฟังก์ชัน |
| `})` | ⚪ เครื่องหมาย | `}` ปิดฟังก์ชัน, `)` ปิด `app.get(` |

กฎที่ต้องจำ
- ฟังก์ชันที่ส่งเข้าไปในวงเล็บของ `app.get(...)` เรียกว่า **callback** Express จะเรียกมันให้ **ทุกครั้งที่มีคำขอเข้ามา** ไม่ใช่ทำทันที
- ใน handler **ต้องตอบกลับ 1 ครั้งเสมอ** (เรียก `ok` หรือ `fail`) ถ้าไม่ตอบ เบราว์เซอร์จะหมุนค้าง
- จุดที่มือใหม่พิมพ์ผิดบ่อยที่สุด คือท้ายสุด `});` ต้องครบ 3 ตัว

> 💡 **เทคนิคพิมพ์ไม่ให้วงเล็บหาย:** พิมพ์โครงก่อนเสมอ `app.get("/api/hello", (req, res) => {` กด Enter 2 ครั้ง แล้วพิมพ์ `});` เลย จากนั้นค่อยกลับไปพิมพ์ข้างใน

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `backend/server.js`

```js
import app from "./app.js";

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`API: http://localhost:${PORT}`));
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | ดึง app จาก app.js | เอามาเปิด port |
| 3 | กำหนดเลข port: ใช้จาก .env ถ้าไม่มีใช้ 5000 | ตอน deploy เปลี่ยน port ได้ผ่าน .env ไม่ต้องแก้โค้ด |
| 4 | เปิด port รอรับคำขอ พอเปิดสำเร็จ พิมพ์ข้อความบอก | ทำให้เบราว์เซอร์เข้า http://localhost:5000 ได้ ข้อความช่วยให้รู้ว่า server ติดแล้ว |

🧩 **Syntax ใหม่ 3: `||` (ถ้าไม่มี ใช้ค่าสำรอง)**

```syntax
[n:ค่าที่อยากใช้] [s:||] [v:ค่าสำรอง]
```

- `process.env.PORT || 5000` = "ถ้าใน .env มี PORT ใช้ค่านั้น ถ้าไม่มี ใช้ 5000"
- `||` พิมพ์ด้วยปุ่ม `Shift + \` 2 ครั้ง

🧩 **Syntax ใหม่ 4: ส่งฟังก์ชันให้ทำทีหลัง (ไม่มีพารามิเตอร์)**

```syntax
[n:app][s:.][p:listen][s:(][n:PORT][s:,] [s:()] [s:=>] [v:คำสั่งที่ทำเมื่อเปิดสำเร็จ][s:)][s:;]
```

- `() =>` = ฟังก์ชันที่ไม่รับค่าอะไร (วงเล็บเปล่า)
- Express จะเรียกฟังก์ชันนี้ **หลังจาก** เปิด port สำเร็จ

🧩 **Syntax ใหม่ 5: Template string (ข้อความที่ใส่ตัวแปรได้)**

```syntax
[s:`][v:ข้อความ][s:${][n:ตัวแปร][s:}][v:ข้อความต่อ][s:`]
```

- ครอบด้วย backtick `` ` `` (ปุ่มซ้ายของเลข 1 ใต้ปุ่ม Esc) **ไม่ใช่** `'` หรือ `"`
- ใส่ค่าตัวแปรด้วย `${ชื่อ}` เช่น `` `API: http://localhost:${PORT}` `` → `"API: http://localhost:5000"`
- ถ้าใช้ `" "` ธรรมดา จะได้ข้อความ `${PORT}` ออกมาตรงๆ ไม่แทนค่า

▶️ **รัน:** ใน terminal (อยู่ในโฟลเดอร์ backend)

```bash
npm run dev
```

ต้องเห็น `API: http://localhost:5000`

> 💡 `npm run dev` เรียก `nodemon` (ตั้งไว้ใน package.json บท 01) ซึ่ง **รีสตาร์ท server ให้เองทุกครั้งที่กดบันทึกไฟล์** ไม่ต้องปิดเปิดใหม่ เปิด terminal นี้ทิ้งไว้ได้ตลอดบท

✅ **ลองเลย:** เปิดเบราว์เซอร์ไปที่ http://localhost:5000/api/hello ต้องเห็น

```json
{"status":"success","message":"สวัสดี","data":{"name":"Eva"}}
```

🎉 นี่คือ API ตัวแรกของเรา

❗ **ถ้าไม่ได้**

| เห็นข้อความ | สาเหตุ | แก้ |
|---|---|---|
| `SyntaxError: Cannot use import statement` | package.json ไม่มี `"type": "module"` | เพิ่มตามบท 01 ขั้น 1.6.1 |
| `SyntaxError: missing ) after argument list` | วงเล็บไม่ครบ มักเป็นท้าย `});` | นับวงเล็บเปิด-ปิดให้ครบคู่ |
| `EADDRINUSE :::5000` | มีโปรแกรมใช้ port 5000 อยู่แล้ว | ปิด terminal เก่าที่รัน server อยู่ |
| `Cannot GET /api/hello` | พิมพ์ URL ไม่ตรงกับบรรทัด 7 | ตรวจตัวสะกด |
| `does not provide an export named 'Ok'` | ชื่อใน `{ }` ไม่ตรงกับตอน export | ใช้ `ok` ตัวเล็ก |
| `'nodemon' is not recognized` | ยังไม่ได้ติดตั้ง | `npm install -D nodemon` |

### ขั้นที่ 3.9.2 ให้ server อ่าน JSON และรับคำขอจากเว็บได้

> 🎯 **ขั้นนี้จะได้:** เตรียม server ให้รับข้อมูล JSON จากหน้าเว็บได้

📖 **Middleware คืออะไร?** คือ "ด่านตรวจ" ที่คำขอต้องวิ่งผ่านทีละด่าน จากบนลงล่าง ก่อนถึงโค้ดของเรา

```text
คำขอ ──▶ [ด่าน cors] ──▶ [ด่านแปลง JSON] ──▶ [route ของเรา] ──▶ ตอบกลับ
```

⌨️ **แก้โค้ด:** เปิด `backend/app.js`
1. เพิ่ม import cors ใต้บรรทัด `import express …` (บรรทัด 3 ด้านล่าง)
2. เพิ่ม 2 บรรทัด `app.use` ใต้ `const app = express();` (บรรทัด 7-8 ด้านล่าง)

```js
import "./env.js";
import express from "express";
import cors from "cors";
import { ok, fail } from "./utils/response.js";

const app = express();
app.use(cors());
app.use(express.json({ limit: "5mb" }));
```

🔍 **อ่านโค้ดทีละบรรทัด** (เฉพาะบรรทัดที่เพิ่ม)

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 3 | ดึง package `cors` | ใช้ในบรรทัด 7 |
| 7 | ติดตั้งด่าน cors ให้ทุกคำขอผ่าน | หน้าเว็บ (port 3000) เรียก API (port 5000) ได้ ถ้าไม่มี เบราว์เซอร์จะบล็อก เพราะถือว่าคนละเว็บกัน |
| 8 | ติดตั้งด่านแปลง body ที่เป็น JSON ให้เป็น object ใน `req.body` | ตอนเพิ่ม/แก้ข้อมูล (POST/PUT) เราจะอ่านค่าจาก `req.body` ได้ `5mb` = รับได้ใหญ่สุด 5 MB เผื่อรูปลายเซ็นกรรมการ |

🧩 **Syntax ใหม่: ติดตั้งด่าน `app.use`**

```syntax
[n:app][s:.][p:use][s:(][n:ด่านที่จะติดตั้ง][s:)][s:;]
```

- `use` เป็น 🟣 คำสั่งของ Express แปลว่า "ให้ทุกคำขอผ่านด่านนี้"
- `cors()` และ `express.json(...)` คือการ **เรียกฟังก์ชันเพื่อสร้างด่าน** จึงต้องมี `( )` ต่อท้าย
- **ลำดับสำคัญ** ด่านที่เขียนก่อน ทำงานก่อน ต้องติดตั้งด่านพวกนี้ **ก่อน** ผูก route ทุกตัว

> ❗ **ถ้าลืมบรรทัด 8** ตอนส่ง POST มา `req.body` จะเป็น `undefined` เป็น bug ที่เจอบ่อยที่สุด

✅ **ลองเลย:** กดบันทึก แล้วรีเฟรช http://localhost:5000/api/hello ต้องยังได้ผลเหมือนเดิม (ขั้นนี้แค่ติดตั้งด่าน ยังไม่เห็นผลต่าง)

### ขั้นที่ 3.9.3 API เช็กสุขภาพระบบ (/api/health)

> 🎯 **ขั้นนี้จะได้:** URL ที่บอกว่า server และฐานข้อมูลทำงานอยู่ (ใช้ตอน deploy และตอนแก้ปัญหา)

⌨️ **แก้โค้ด:** ใน `backend/app.js`
1. เพิ่ม `import pool from "./db.js";` ใต้ import อื่นๆ
2. **ลบ** route `/api/hello` ทิ้ง (บรรทัด `app.get("/api/hello" …` ถึง `});`) แล้วพิมพ์ route ใหม่นี้แทน

```js
// เช็กว่า API และฐานข้อมูลทำงาน
app.get("/api/health", async (req, res) => {
  const [rows] = await pool.query("SELECT 1 AS ok");
  ok(res, { db: rows[0].ok }, "API พร้อมใช้งาน");
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | คอมเมนต์ | บอกหน้าที่ของ route นี้ |
| 2 | ผูก GET `/api/health` กับฟังก์ชันแบบ `async` | ตอน deploy เปิด URL นี้ดูว่าระบบติดไหม |
| 3 | ถาม MySQL ด้วย SQL ง่ายที่สุด `SELECT 1` ได้ `[{ ok: 1 }]` | ถ้าฐานข้อมูลดับ บรรทัดนี้จะ error ทำให้รู้ทันที |
| 4 | ตอบกลับ `db: 1` | หน้าเว็บหรือคนดูรู้ว่า "API ติด + ฐานข้อมูลติด" |
| 5 | ปิดฟังก์ชันและวงเล็บ | จบ route |

🧩 **Syntax ใหม่ 1: `async` (ฟังก์ชันที่มีการรอ)**

```syntax
[n:app][s:.][p:get][s:(][v:"/URL"][s:,] [k:async] [s:(][n:req][s:,] [n:res][s:)] [s:=>] [s:{]
  [k:const] [s:\[][n:rows][s:\]] [s:=] [k:await] [n:pool][s:.][p:query][s:(][v:"SQL"][s:)][s:;]
[s:}][s:)][s:;]
```

กฎที่ต้องจำ
- **ฟังก์ชันไหนข้างในมี `await` ต้องเขียน `async` นำหน้าฟังก์ชันนั้น** ไม่งั้น error `await is only valid in async functions`
- `async` วางไว้ **หน้าวงเล็บ** `(req, res)`
- route ที่คุยกับฐานข้อมูล = มี `await` = ต้องมี `async` เสมอ (เกือบทุก route ในระบบเรา)

🧩 **Syntax ใหม่ 2: หยิบค่าจาก array และ object**

```syntax
[n:rows][s:\[][v:0][s:\]][s:.][n:ok]
```

| ส่วน | ทำอะไร | ได้ค่า |
|---|---|---|
| `rows` | array ของแถว | `[{ ok: 1 }]` |
| `[0]` | หยิบช่องที่ 0 (**ช่องแรกคือ 0 ไม่ใช่ 1**) | `{ ok: 1 }` |
| `.ok` | หยิบช่องชื่อ ok ของ object | `1` |

> 💡 `AS ok` ใน SQL คือการตั้งชื่อคอลัมน์ เลยหยิบด้วย `.ok` ได้ ถ้าตั้ง `AS abc` ก็ต้องหยิบด้วย `.abc`

✅ **ลองเลย:** เปิด http://localhost:5000/api/health ต้องเห็น

```json
{"status":"success","message":"API พร้อมใช้งาน","data":{"db":1}}
```

### ขั้นที่ 3.9.4 ตอบ 404 เมื่อ URL ผิด

> 🎯 **ขั้นนี้จะได้:** พิมพ์ URL มั่วแล้วได้คำตอบรูปแบบเดียวกับระบบ แทนหน้า HTML ของ Express

📖 **ลองดูปัญหาก่อน:** เปิด http://localhost:5000/api/abc จะเห็นหน้า HTML `Cannot GET /api/abc` ซึ่งไม่ใช่รูปแบบ `{status, message, data}` ของเรา

⌨️ **แก้โค้ด:** เพิ่มใน `backend/app.js` **ต่อจาก route ทั้งหมด แต่ก่อน `export default app;`**

```js
// ไม่พบ endpoint
app.use((req, res) => fail(res, 404, "ไม่พบ endpoint นี้"));
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | คอมเมนต์ | - |
| 2 | ติดตั้งด่านสุดท้าย: ใครมาถึงตรงนี้ ตอบ 404 | คำขอที่ URL ผิดได้คำตอบรูปแบบเดียวกับระบบ หน้าเว็บโชว์ข้อความได้ |

📖 **ทำไมต้องอยู่ล่างสุด?** Express ตรวจจากบนลงล่าง ถ้าคำขอผ่าน route ทุกตัวแล้วไม่มีใครตอบ ก็จะตกมาถึงบรรทัดนี้ แปลว่า "ไม่มี URL นี้" ถ้าเอาไว้บนสุด ทุกคำขอจะได้ 404 หมด

> 🧩 syntax ในขั้นนี้สอนไปแล้วทั้งหมด: `app.use` (3.9.2), arrow function แบบคำสั่งเดียวไม่มี `{ }` (3.8.1)

✅ **ลองเลย:** เปิด http://localhost:5000/api/abc ต้องเห็น

```json
{"status":"error","message":"ไม่พบ endpoint นี้","data":null}
```

### ขั้นที่ 3.9.5 ดัก error ทั้งระบบไว้ที่เดียว

> 🎯 **ขั้นนี้จะได้:** ถ้าโค้ดพังตรงไหน ผู้ใช้จะได้ข้อความภาษาไทยที่เหมาะสม ไม่ใช่ server ค้าง (เกณฑ์ 6.7)

📖 **Error handler** คือด่านพิเศษ Express จะส่ง error ทุกตัวที่เกิดใน route มาที่นี่
(Express 5 ส่ง error จาก `async` มาให้เอง ไม่ต้องเขียน `try/catch` ทุก route)

⌨️ **แก้โค้ด:** เพิ่มต่อจากบรรทัด 404 (ยังอยู่ก่อน `export default app;`)

```js
// error ที่ไม่ได้ดักไว้ (Express 5 ส่ง error จาก async มาที่นี่เอง)
app.use((err, req, res, next) => {
  console.error(err);
  fail(res, 500, "เกิดข้อผิดพลาดในระบบ");
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 2 | ติดตั้งด่านที่รับ 4 ค่า | Express รู้ว่าด่านที่รับ 4 ค่าคือ "ด่านรับ error" |
| 3 | พิมพ์ error เต็มๆ ใน terminal (`console.error` = พิมพ์แบบ error) | ให้โปรแกรมเมอร์ดูว่าพังเพราะอะไร |
| 4 | ตอบผู้ใช้ 500 ข้อความสุภาพ | ผู้ใช้ไม่เห็นรายละเอียดภายใน (ปลอดภัยกว่า) และ server ไม่ดับ |

🧩 **Syntax ใหม่: ด่านรับ error (4 พารามิเตอร์)**

```syntax
[n:app][s:.][p:use][s:(][s:(][n:err][s:,] [n:req][s:,] [n:res][s:,] [n:next][s:)] [s:=>] [s:{]
  [v:จัดการ error]
[s:}][s:)][s:;]
```

กฎที่ต้องจำ
- ต้องมี **ครบ 4 ตัว** แม้ไม่ได้ใช้ `next` ถ้ามี 3 ตัว Express จะคิดว่าเป็นด่านธรรมดา
- ตัวแรก `err` คือ error ที่เกิดขึ้น
- ต้องอยู่ **ล่างสุด** (ต่อจากด่าน 404)

✅ **ลองเลย (ทดสอบตอนฐานข้อมูลดับ):**
1. เปิด terminal ใหม่ พิมพ์ `docker stop eva_mysql`
2. เปิด http://localhost:5000/api/health ต้องได้ `{"status":"error","message":"เกิดข้อผิดพลาดในระบบ","data":null}` และ server **ไม่ดับ**
3. พิมพ์ `docker start eva_mysql` รอ 20 วินาที แล้วรีเฟรช ต้องกลับมาเป็น success

### ขั้นที่ 3.9.6 แปล error ที่เกิดจากข้อมูลผู้ใช้เป็น 400

> 🎯 **ขั้นนี้จะได้:** ตอบ 400 (ข้อมูลผิด) แทน 500 (ระบบพัง) เมื่อความผิดมาจากข้อมูลที่ส่งมา

📖 บาง error ไม่ใช่ความผิดของระบบ แต่เป็นเพราะข้อมูลที่ส่งมาไม่ถูก เช่น
- เพิ่ม username ที่มีอยู่แล้ว (ตาราง users ตั้ง `UNIQUE` ไว้) MySQL โยน error รหัส `ER_DUP_ENTRY`
- ใส่วันปิดก่อนวันเปิด (ตั้ง `CHECK` ไว้ในบท 02) MySQL โยน error รหัส `ER_CHECK_CONSTRAINT_VIOLATED`

กรณีแบบนี้ควรตอบ **400** ไม่ใช่ 500

⌨️ **แก้โค้ด:** ใน error handler เพิ่ม 4 บรรทัด `if` (บรรทัด 2-6 ด้านล่าง) **ก่อน** `console.error(err);`

```js
app.use((err, req, res, next) => {
  if (err.status === 400) return fail(res, 400, "รูปแบบข้อมูลที่ส่งมาไม่ถูกต้อง"); // เช่น JSON พัง
  // error จาก MySQL ที่เกิดจากข้อมูลผู้ใช้ ตอบ 400
  if (err.code === "ER_DUP_ENTRY") return fail(res, 400, "ข้อมูลซ้ำกับที่มีอยู่แล้ว");
  if (err.code === "ER_NO_REFERENCED_ROW_2") return fail(res, 400, "ไม่พบข้อมูลที่อ้างอิง");
  if (err.code === "ER_CHECK_CONSTRAINT_VIOLATED") return fail(res, 400, "ข้อมูลไม่อยู่ในช่วงที่กำหนด");
  console.error(err);
  fail(res, 500, "เกิดข้อผิดพลาดในระบบ");
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร (เกิดตอนไหน) |
|---|---|---|
| 2 | ถ้า error มี status 400 ตอบ 400 แล้วจบ | ตอนส่ง body ที่ไม่ใช่ JSON ที่ถูกต้อง เช่น `{"title": ` (ปิดวงเล็บไม่ครบ) |
| 3 | คอมเมนต์ | - |
| 4 | ถ้ารหัส error คือข้อมูลซ้ำ ตอบ 400 | เพิ่ม username `hr` ซ้ำ |
| 5 | ถ้ารหัส error คืออ้างถึง id ที่ไม่มี ตอบ 400 | เพิ่มตัวชี้วัดในหัวข้อ id 999 (FOREIGN KEY) |
| 6 | ถ้ารหัส error คือผิดเงื่อนไข CHECK ตอบ 400 | วันปิดก่อนวันเปิด |
| 7-8 | error อื่นๆ ที่ไม่รู้จัก พิมพ์ลง terminal แล้วตอบ 500 | เหมือนขั้น 3.9.5 |

🧩 **Syntax ใหม่ 1: `if` (ถ้า...ให้ทำ...)**

โครงสร้าง (แบบคำสั่งเดียว เขียนบรรทัดเดียว)

```syntax
[k:if] [s:(][v:เงื่อนไข][s:)] [n:คำสั่งที่ทำเมื่อเงื่อนไขเป็นจริง][s:;]
```

เทียบกับบรรทัด 4

```syntax
[k:if] [s:(][p:err][s:.][p:code] [s:===] [v:"ER_DUP_ENTRY"][s:)] [k:return] [n:fail][s:(][n:res][s:,] [v:400][s:,] [v:"ข้อมูลซ้ำ..."][s:)][s:;]
```

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `if` | 🔵 syntax | "ถ้า" |
| `( … )` | ⚪ เครื่องหมาย | ครอบเงื่อนไข **ต้องมีวงเล็บเสมอ** |
| `err.code` | 🟣 MySQL กำหนด | รหัส error ที่ mysql2 แนบมา |
| `===` | ⚪ เครื่องหมาย | "เท่ากับไหม" ได้ผลเป็น true/false |
| `"ER_DUP_ENTRY"` | 🟠 ค่า | รหัสที่ MySQL กำหนด ต้องสะกดตามเป๊ะ |
| `return` | 🔵 syntax | "จบฟังก์ชันตรงนี้" |

ถ้ามีหลายคำสั่ง ใช้ `{ }` ครอบ

```syntax
[k:if] [s:(][v:เงื่อนไข][s:)] [s:{]
  [n:คำสั่งที่ 1][s:;]
  [n:คำสั่งที่ 2][s:;]
[s:}]
```

🧩 **Syntax ใหม่ 2: เครื่องหมายเปรียบเทียบ**

| เครื่องหมาย | แปลว่า | ตัวอย่าง |
|---|---|---|
| `===` | เท่ากับ | `code === 200` |
| `!==` | ไม่เท่ากับ | `role !== "hr"` |
| `>` `<` `>=` `<=` | มากกว่า น้อยกว่า ... | `score >= 3` |

> ❗ **`=` กับ `===` คนละเรื่องกัน:** `=` คือ "เก็บค่า" (ขั้น 3.7.2) ส่วน `===` คือ "เท่ากับไหม" ใน `if` ต้องใช้ `===` เสมอ (JavaScript มี `==` 2 ตัวด้วย แต่ให้ใช้ 3 ตัวเท่านั้น ปลอดภัยกว่า)

🧩 **Syntax ใหม่ 3: `return` (จบฟังก์ชันทันที)**

- เมื่อเจอ `return` ฟังก์ชันจะหยุด บรรทัดที่เหลือข้างล่างไม่ทำ
- **ทำไมต้องมี `return` หน้า `fail`?** ถ้าไม่ใส่ โค้ดจะทำบรรทัดต่อไปด้วย แล้วตอบกลับซ้ำเป็นครั้งที่ 2 ได้ error `Cannot set headers after they are sent`
- **จำง่ายๆ: ตอบกลับแล้วยังมีโค้ดต่อจากนั้น ต้องใส่ `return` นำหน้าเสมอ**

✅ **ลองเลย:** ขั้นนี้จะได้ทดสอบจริงในขั้น 3.10.7 (ส่งวันที่ผิด)

## 3.10 API หัวข้อการประเมิน (CRUD)

📖 **Router คืออะไร?** ถ้าเขียน API ทุกตัวไว้ใน app.js ไฟล์จะยาวหลายร้อยบรรทัด หาอะไรไม่เจอ
เราจึงแยกไฟล์ตามเรื่อง **1 ไฟล์ = 1 กลุ่มข้อมูล** เช่น `routes/topics.js` ดูแลเฉพาะหัวข้อการประเมิน (เกณฑ์ 6.11)

ในหัวข้อนี้จะสร้าง 5 API ทีละตัว

| ขั้น | Method | URL | ทำอะไร |
|---|---|---|---|
| 3.10.2-3.10.4 | GET | `/api/topics` | ดูหัวข้อทั้งหมด |
| 3.10.5 | GET | `/api/topics/:id` | ดูหัวข้อเดียว |
| 3.10.6 | POST | `/api/topics` | เพิ่มหัวข้อ |
| 3.10.7 | PUT | `/api/topics/:id` | แก้หัวข้อ |
| 3.10.8 | DELETE | `/api/topics/:id` | ลบหัวข้อ |

### ขั้นที่ 3.10.1 สร้างไฟล์ router เปล่า แล้วต่อเข้า app

> 🎯 **ขั้นนี้จะได้:** โครงไฟล์ routes/topics.js ที่ต่อกับ app แล้ว พร้อมเติม API

⌨️ **พิมพ์โค้ด:** สร้างไฟล์ใหม่ `backend/routes/topics.js`

```js
import { Router } from "express";
import pool from "../db.js";
import { ok, fail } from "../utils/response.js";

const router = Router();

// (API ต่างๆ จะเขียนตรงนี้)

export default router;
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | ดึงตัวสร้าง Router จาก express (แบบมีชื่อ ใช้ `{ }`) | ใช้สร้าง router ในบรรทัด 5 |
| 2 | ดึง pool (`../` = ขึ้นไป 1 ชั้น เพราะไฟล์นี้อยู่ในโฟลเดอร์ routes) | ใช้คุยกับฐานข้อมูลในทุก API ของไฟล์นี้ |
| 3 | ดึง ok / fail | ใช้ตอบกลับ |
| 5 | สร้าง router เก็บไว้ในชื่อ `router` | router = "app ขนาดเล็ก" ผูก URL ได้เหมือน app แต่ดูแลแค่เรื่องหัวข้อ |
| 7 | คอมเมนต์ที่วางไว้ชั่วคราว | จุดที่จะพิมพ์ API ในขั้นต่อไป |
| 9 | ส่ง router ออกจากไฟล์ | ให้ app.js เอาไปต่อ |

> 🧩 syntax ในไฟล์นี้สอนไปแล้ว: import แบบมีชื่อ `{ }` (3.9.1), `const` (3.7.2), `export default` (3.7.2)
> ข้อสังเกต: `Router` เป็น 🟣 ชื่อที่ express กำหนด (R ตัวใหญ่) ส่วน `router` เป็น 🟢 ชื่อที่เราตั้ง (r ตัวเล็ก) คนละตัวกัน

⌨️ **แก้โค้ด:** เปิด `backend/app.js`
1. เพิ่ม import ใต้ import อื่นๆ

```js
import topicRoutes from "./routes/topics.js";
```

2. เพิ่มบรรทัดนี้ **ใต้ route `/api/health`** (และต้องอยู่ **เหนือ** บรรทัด 404)

```js
app.use("/api/topics", topicRoutes);
```

🔍 **อ่านโค้ด**

| โค้ด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| `import topicRoutes from …` | ดึง router จากไฟล์ topics.js ตั้งชื่อว่า `topicRoutes` | เอามาต่อเข้า app |
| `app.use("/api/topics", topicRoutes)` | "คำขอที่ URL ขึ้นต้นด้วย `/api/topics` ส่งต่อไปที่ topicRoutes" | แยกงานให้แต่ละไฟล์ดูแล |

🧩 **Syntax ใหม่: `app.use` แบบมี URL นำหน้า**

```syntax
[n:app][s:.][p:use][s:(][v:"/URL นำหน้า"][s:,] [n:router][s:)][s:;]
```

- URL ใน router จะ **ต่อท้าย** URL นำหน้า
- ใน topics.js เขียน `"/"` จะหมายถึง `/api/topics`
- ใน topics.js เขียน `"/:id"` จะหมายถึง `/api/topics/3`

✅ **ลองเลย:** เปิด http://localhost:5000/api/topics ตอนนี้ยังได้ 404 "ไม่พบ endpoint นี้" (ถูกต้อง เพราะ router ยังว่าง) แต่ terminal ต้อง **ไม่มี error สีแดง**

### ขั้นที่ 3.10.2 GET ดูหัวข้อทั้งหมด (แบบง่าย)

> 🎯 **ขั้นนี้จะได้:** เปิด /api/topics แล้วเห็นหัวข้อจากฐานข้อมูล

⌨️ **พิมพ์โค้ด:** ใน `routes/topics.js` พิมพ์แทนบรรทัด `// (API ต่างๆ จะเขียนตรงนี้)`

```js
// GET /api/topics  หัวข้อทั้งหมด
router.get("/", async (req, res) => {
  const [topics] = await pool.query("SELECT * FROM evaluation_topics ORDER BY id");
  ok(res, topics);
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | คอมเมนต์บอก Method + URL เต็ม | ให้คนอ่านรู้ทันทีว่า route นี้คือ URL อะไร (เพราะในไฟล์เขียนแค่ `/`) |
| 2 | ผูก GET `/` (= `/api/topics`) | หน้า "จัดการหัวข้อ" ของ hr จะเรียก URL นี้ |
| 3 | ดึงทุกหัวข้อ เรียงตาม id เก็บใน `topics` | ข้อมูลที่จะโชว์ในตาราง |
| 4 | ตอบ 200 พร้อมรายการ | ส่งข้อมูลให้หน้าเว็บ |

> 🧩 syntax สอนไปแล้วทั้งหมด: route (3.9.1), `async`/`await` (3.9.3, 3.7.3), แกะ array (3.7.3)
> ข้อสังเกต: เหมือน `app.get(...)` ทุกอย่าง แค่เปลี่ยน `app` เป็น `router`

✅ **ลองเลย:** เปิด http://localhost:5000/api/topics ต้องเห็นหัวข้อ 2 รายการ

```json
{"status":"success","message":"สำเร็จ","data":[{"id":1,"title":"ด้านการจัดการเรียนการสอน",...},{"id":2,...}]}
```

> 💡 **อ่าน JSON ยาก?** Chrome และ Edge มีช่อง "Pretty-print" (จัดรูปแบบ) ให้ติ๊กด้านบนของหน้า จะอ่านง่ายขึ้นมาก

> 🎉 นี่คือ **แพตเทิร์นที่ 1: อ่านทั้งหมด** ซึ่งจะใช้ซ้ำทั้งระบบ
> ```js
> const [rows] = await pool.query("SELECT ...");
> ok(res, rows);
> ```

### ขั้นที่ 3.10.3 เพิ่มช่อง is_open (หัวข้อเปิดอยู่ไหม)

> 🎯 **ขั้นนี้จะได้:** แต่ละหัวข้อมีช่อง `is_open` บอกว่าวันนี้อยู่ในช่วงเปิดประเมินไหม (เกณฑ์ 5.1.2)

📖 หัวข้อมี `start_date` (วันเปิด) และ `end_date` (วันปิด) หน้าเว็บอยากรู้ว่า **วันนี้** เปิดอยู่ไหม
เราให้ MySQL คำนวณให้เลย ด้วย SQL นี้

```sql
CURDATE() BETWEEN start_date AND end_date
```

= "วันนี้ อยู่ระหว่าง วันเปิด ถึง วันปิด ไหม" ได้ `1` (ใช่) หรือ `0` (ไม่ใช่)

⌨️ **แก้โค้ด:** ใน `routes/topics.js`
1. เพิ่มค่าคงที่นี้ **ใต้** `const router = Router();`

```js
// is_open = วันนี้อยู่ในช่วงเปิด-ปิดหรือไม่
const TOPIC_FIELDS = "*, (CURDATE() BETWEEN start_date AND end_date) AS is_open";
```

2. แก้ SQL ในขั้น 3.10.2 จาก `"SELECT * FROM …"` เป็น

```js
  const [topics] = await pool.query(`SELECT ${TOPIC_FIELDS} FROM evaluation_topics ORDER BY id`);
```

🔍 **อ่านโค้ด**

| โค้ด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| `const TOPIC_FIELDS = "…"` | เก็บส่วน "คอลัมน์ที่จะดึง" ไว้ในตัวแปร | จะใช้อีกในขั้น 3.10.5 ไม่ต้องพิมพ์ซ้ำ ถ้าแก้ก็แก้ที่เดียว |
| `*` | ทุกคอลัมน์ของตาราง | - |
| `(CURDATE() BETWEEN …) AS is_open` | คำนวณ 1/0 ตั้งชื่อคอลัมน์ว่า is_open | หน้าเว็บโชว์ป้าย "เปิด/ปิด" และใช้ห้ามแก้ไขเมื่อหัวข้อปิดแล้ว |
| `` `SELECT ${TOPIC_FIELDS} FROM …` `` | template string แทนค่าตัวแปรลงใน SQL | ได้ SQL เต็ม `SELECT *, (CURDATE() …) AS is_open FROM …` |

> 🧩 syntax สอนไปแล้ว: template string (3.9.1)
> ชื่อตัวแปรตัวใหญ่ทั้งหมด (`TOPIC_FIELDS`) เป็นธรรมเนียมบอกว่า "ค่าคงที่ที่ตั้งไว้ใช้ซ้ำ" ไม่ใช่ syntax บังคับ

> 💡 **อ้าว! นี่ต่อข้อความใน SQL ไม่ผิดกฎขั้น 3.7.5 หรอ?** ไม่ผิด เพราะ `TOPIC_FIELDS` เป็นข้อความที่ **เราเขียนเอง** ไม่ได้มาจากผู้ใช้ กฎคือ "ค่าจากผู้ใช้ต้องผ่าน `?`"

✅ **ลองเลย:** รีเฟรช /api/topics ทุกหัวข้อต้องมี `"is_open":1` (ถ้าวันนี้อยู่ในช่วงวันที่ของข้อมูลตัวอย่าง)

### ขั้นที่ 3.10.4 แนบตัวชี้วัดไปกับแต่ละหัวข้อ

> 🎯 **ขั้นนี้จะได้:** แต่ละหัวข้อมีช่อง `indicators` เป็นรายการตัวชี้วัดของหัวข้อนั้น หน้าเว็บจะได้ไม่ต้องเรียก API อีกรอบ

📖 **แนวคิด:** ดึง 2 ครั้ง แล้วจับคู่กันใน JavaScript
1. ดึงหัวข้อทั้งหมด (ทำแล้ว)
2. ดึงตัวชี้วัดทั้งหมด
3. วนทีละหัวข้อ เลือกตัวชี้วัดที่ `topic_id` ตรงกับ `id` ของหัวข้อ

```text
topics:      [ {id:1}, {id:2} ]
indicators:  [ {topic_id:1}, {topic_id:1}, {topic_id:2} ]
                    │              │            │
ผลลัพธ์:     [ {id:1, indicators:[▲, ▲]}, {id:2, indicators:[▲]} ]
```

⌨️ **แก้โค้ด:** ใน route GET `/` เพิ่ม 2 บรรทัด (บรรทัด 3-4 ด้านล่าง) **ระหว่าง** บรรทัด query หัวข้อ กับบรรทัด `ok(res, topics);`

```js
router.get("/", async (req, res) => {
  const [topics] = await pool.query(`SELECT ${TOPIC_FIELDS} FROM evaluation_topics ORDER BY id`);
  const [indicators] = await pool.query("SELECT * FROM indicators ORDER BY id");
  for (const t of topics) t.indicators = indicators.filter((i) => i.topic_id === t.id);
  ok(res, topics);
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 3 | ดึงตัวชี้วัดทุกตัวเก็บใน `indicators` | เตรียมไว้จับคู่กับหัวข้อ |
| 4 | วนทีละหัวข้อ แล้วสร้างช่องใหม่ `indicators` ในหัวข้อนั้น = ตัวชี้วัดที่ `topic_id` ตรงกับ `id` ของหัวข้อ | หน้าเว็บโชว์ตัวชี้วัดใต้แต่ละหัวข้อได้เลย ใช้ API ครั้งเดียว |

🧩 **Syntax ใหม่ 1: `for … of` (วนทีละตัว)**

โครงสร้าง

```syntax
[k:for] [s:(][k:const] [n:ชื่อเรียกแต่ละตัว] [k:of] [n:array][s:)] [v:คำสั่งที่ทำทุกรอบ][s:;]
```

เทียบกับบรรทัด 4

```syntax
[k:for] [s:(][k:const] [n:t] [k:of] [n:topics][s:)] [n:t][s:.][n:indicators] [s:=] [s:...][s:;]
```

| คำ | ชนิด | หน้าที่ |
|---|---|---|
| `for` | 🔵 syntax | "วนซ้ำ" |
| `const t` | 🔵 + 🟢 | ตั้งชื่อเรียก "ตัวที่กำลังวนถึง" รอบแรก t = หัวข้อแรก รอบสอง t = หัวข้อที่สอง |
| `of` | 🔵 syntax | "ใน" |
| `topics` | 🟢 ตั้งเอง | array ที่จะวน |

- ถ้าทำหลายคำสั่งต่อรอบ ใช้ `{ }` ครอบ เหมือน `if`
- `t.indicators = …` คือ **สร้างช่องใหม่** ชื่อ indicators ใน object t (ถ้ายังไม่มี จะสร้างให้)

🧩 **Syntax ใหม่ 2: `.filter()` (คัดเฉพาะตัวที่ตรงเงื่อนไข)**

โครงสร้าง

```syntax
[n:array][s:.][p:filter][s:(][s:(][n:แต่ละตัว][s:)] [s:=>] [v:เงื่อนไข][s:)]
```

ตัวอย่างง่ายๆ

```js
[1, 5, 8, 2].filter((n) => n > 3);   // ได้ [5, 8]
```

เทียบกับบรรทัด 4

```syntax
[n:indicators][s:.][p:filter][s:(][s:(][n:i][s:)] [s:=>] [n:i][s:.][p:topic_id] [s:===] [n:t][s:.][p:id][s:)]
```

- `filter` เป็น 🟣 คำสั่งที่ทุก array มีให้
- ส่งฟังก์ชันเข้าไป 1 ตัว `filter` จะเรียกฟังก์ชันนั้นกับ **ทีละตัว** ใน array
- ตัวไหนเงื่อนไขได้ `true` → เก็บ / ได้ `false` → ทิ้ง
- ได้ **array ใหม่** (array เดิมไม่เปลี่ยน)
- `topic_id` และ `id` เป็น 🟣 ชื่อคอลัมน์ในฐานข้อมูล (ตั้งไว้ในบท 02) ต้องสะกดตรง

✅ **ลองเลย:** รีเฟรช /api/topics แต่ละหัวข้อต้องมี `"indicators":[...]` ซ้อนอยู่ข้างใน

### ขั้นที่ 3.10.5 GET ดูหัวข้อเดียวตาม id

> 🎯 **ขั้นนี้จะได้:** เปิด /api/topics/1 แล้วได้หัวข้อ id 1 ถ้า id ไม่มีได้ 404

⌨️ **พิมพ์โค้ด:** เพิ่มใน `routes/topics.js` ต่อจาก route GET `/`

```js
// GET /api/topics/:id
router.get("/:id", async (req, res) => {
  const [rows] = await pool.query(`SELECT ${TOPIC_FIELDS} FROM evaluation_topics WHERE id = ?`, [req.params.id]);
  if (!rows[0]) return fail(res, 404, "ไม่พบหัวข้อการประเมิน");
  const [indicators] = await pool.query("SELECT * FROM indicators WHERE topic_id = ? ORDER BY id", [req.params.id]);
  ok(res, { ...rows[0], indicators });
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 2 | ผูก GET `/:id` เช่น `/api/topics/1` | หน้าแก้ไขหัวข้อ และหน้าให้คะแนน เรียกเพื่อดูหัวข้อเดียว |
| 3 | ดึงหัวข้อที่ id ตรงกับใน URL (ใช้ `?` เพราะ id มาจากผู้ใช้) ได้ 0 หรือ 1 แถว | หาหัวข้อที่ต้องการ |
| 4 | ถ้าไม่มีแถวแรก ตอบ 404 แล้วจบ | กันกรณีขอ id ที่ไม่มี (หรือถูกลบไปแล้ว) |
| 5 | ดึงตัวชี้วัดของหัวข้อนี้ | ให้หน้าเว็บโชว์ตัวชี้วัดพร้อมกัน |
| 6 | รวมหัวข้อกับตัวชี้วัดเป็น object เดียวแล้วตอบ | หน้าเว็บได้ข้อมูลครบในครั้งเดียว |

🧩 **Syntax ใหม่ 1: `:id` ใน URL และ `req.params`**

```syntax
[n:router][s:.][p:get][s:(][v:"/][s::][n:ชื่อช่อง][v:"][s:,] [s:...][s:)]
```

- `:` นำหน้า = "ช่องว่างให้เติม" ชื่อหลัง `:` ตั้งเอง
- เปิด `/api/topics/7` → Express เก็บ `"7"` ไว้ที่ `req.params.id`
- ชื่อหลัง `req.params.` ต้องตรงกับชื่อหลัง `:` (ตั้ง `/:topicId` ก็ต้องอ่าน `req.params.topicId`)
- ค่าที่ได้เป็น **ข้อความ** เสมอ (`"7"` ไม่ใช่ `7`)

🧩 **Syntax ใหม่ 2: `!` (ไม่ / ไม่มี)**

```syntax
[s:!][n:ค่า]
```

- `!rows[0]` = "ไม่มี rows[0]" → เป็นจริงเมื่อ query ไม่เจอแถวไหนเลย
- `!` กลับค่า: จริง → เท็จ, เท็จ → จริง
- ค่าที่นับเป็น "ไม่มี": `undefined`, `null`, `0`, `""` (ข้อความว่าง)

🧩 **Syntax ใหม่ 3: `...` (กระจาย object)**

```syntax
[s:{] [s:...][n:objectเดิม][s:,] [n:ช่องที่เพิ่ม] [s:}]
```

ตัวอย่าง

```js
const a = { id: 1, title: "ก" };
const b = { ...a, indicators: [] };   // { id: 1, title: "ก", indicators: [] }
```

- `...a` = "เอาทุกช่องของ a มาใส่ตรงนี้"
- `{ ...rows[0], indicators }` = ทุกช่องของหัวข้อ + ช่อง indicators (แบบย่อชื่อ ขั้น 3.8.1)

✅ **ลองเลย**
- http://localhost:5000/api/topics/1 → ได้หัวข้อ id 1 พร้อม indicators
- http://localhost:5000/api/topics/999 → ได้ `{"status":"error","message":"ไม่พบหัวข้อการประเมิน","data":null}`

> 🎉 นี่คือ **แพตเทิร์นที่ 2: อ่าน 1 รายการ (ไม่พบตอบ 404)**
> ```js
> const [rows] = await pool.query("SELECT ... WHERE id = ?", [req.params.id]);
> if (!rows[0]) return fail(res, 404, "ไม่พบ...");
> ok(res, rows[0]);
> ```

### ขั้นที่ 3.10.6 POST เพิ่มหัวข้อ + เริ่มใช้ Thunder Client

> 🎯 **ขั้นนี้จะได้:** ส่งข้อมูลไปเพิ่มหัวข้อใหม่ได้ และใช้ Thunder Client เป็น

📖 เบราว์เซอร์พิมพ์ URL ได้แค่ GET ถ้าจะทดสอบ POST / PUT / DELETE ต้องใช้โปรแกรมช่วย เราใช้ **Thunder Client** (ส่วนเสริมใน VS Code ติดตั้งในบท 01)

⌨️ **พิมพ์โค้ด:** เพิ่มใน `routes/topics.js` ต่อจาก route GET `/:id`

```js
// POST /api/topics  body: { title, description, start_date, end_date }
router.post("/", async (req, res) => {
  const { title, description, start_date, end_date } = req.body;
  if (!title || !start_date || !end_date) return fail(res, 400, "กรุณากรอกข้อมูลให้ครบ"); // บท 04 จะเปลี่ยนเป็น Zod
  const [result] = await pool.query(
    "INSERT INTO evaluation_topics (title, description, start_date, end_date) VALUES (?, ?, ?, ?)",
    [title, description, start_date, end_date]
  );
  ok(res, { id: result.insertId }, "เพิ่มหัวข้อสำเร็จ", 201);
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 1 | คอมเมนต์บอก URL และหน้าตา body | คนเขียนหน้าเว็บรู้ว่าต้องส่งอะไรมา |
| 2 | ผูก **POST** `/` (= `/api/topics`) | ฟอร์ม "เพิ่มหัวข้อ" ของ hr เรียก URL นี้ |
| 3 | แกะค่า 4 ช่องออกจาก body ที่ส่งมา | ได้ตัวแปร 4 ตัวไว้ใช้ข้างล่าง |
| 4 | ถ้าไม่มี title หรือวันเปิด หรือวันปิด ตอบ 400 แล้วจบ | กันข้อมูลไม่ครบลงฐานข้อมูล (บท 04 จะเปลี่ยนเป็น Zod ที่ละเอียดกว่า) |
| 5 | เริ่มเรียก query (ยาว เลยแยกบรรทัด) | - |
| 6 | SQL INSERT มี `?` 4 ตัว | เพิ่มแถวใหม่ในตาราง |
| 7 | ค่า 4 ตัว เรียงตรงกับ `?` | ส่งค่าอย่างปลอดภัย (ขั้น 3.7.5) |
| 8 | ปิดวงเล็บ query | - |
| 9 | ตอบ **201** พร้อม id ของแถวใหม่ | หน้าเว็บรู้ว่าเพิ่มสำเร็จ และรู้ id ใหม่ (เช่น เอาไปเปิดหน้าเพิ่มตัวชี้วัดต่อ) |

🧩 **Syntax ใหม่ 1: `const { … } = object` (แกะ object)**

โครงสร้าง

```syntax
[k:const] [s:{] [n:ชื่อช่อง1][s:,] [n:ชื่อช่อง2] [s:}] [s:=] [n:object][s:;]
```

ตัวอย่าง

```js
const { title, start_date } = { title: "ก", start_date: "2026-11-01", x: 9 };
// title = "ก", start_date = "2026-11-01" (x ไม่ได้เอามา)
```

| | แกะ array `[ ]` (ขั้น 3.7.3) | แกะ object `{ }` |
|---|---|---|
| ดึงตาม | ลำดับ (ช่องที่ 1, 2, …) | **ชื่อช่อง** |
| ตั้งชื่อ | ตั้งอะไรก็ได้ | ต้อง **ตรงกับชื่อช่อง** ใน object |

> 💡 บรรทัด 3 สั้นกว่าการเขียนแยก `const title = req.body.title;` ทีละบรรทัด 4 ครั้ง

🧩 **Syntax ใหม่ 2: `||` ในเงื่อนไข (หรือ)**

```syntax
[k:if] [s:(][v:เงื่อนไข1] [s:||] [v:เงื่อนไข2] [s:||] [v:เงื่อนไข3][s:)] [v:...]
```

- `||` ใน `if` แปลว่า "หรือ" → ข้อใดข้อหนึ่งจริง ก็ทำ
- `!title || !start_date || !end_date` = "ไม่มีชื่อ **หรือ** ไม่มีวันเปิด **หรือ** ไม่มีวันปิด"
- ถ้าต้องการ "และ" (ต้องจริงทุกข้อ) ใช้ `&&`

🧩 **Syntax ใหม่ 3: เรียกคำสั่งแบบแยกหลายบรรทัด**

```syntax
[n:pool][s:.][p:query][s:(]
  [v:"SQL ยาวๆ"][s:,]
  [s:\[][n:ค่า1][s:,] [n:ค่า2][s:\]]
[s:)][s:;]
```

- ค่าที่ส่งให้คำสั่งยาวเกินไป ขึ้นบรรทัดใหม่ได้ โดยขึ้นหลัง `(` หรือหลัง `,`
- ย่อหน้าค่าข้างใน แล้วปิด `)` ในบรรทัดของตัวเอง จะเห็นชัดว่าเปิด-ปิดตรงไหน

> 💡 **`result.insertId`** ตอน INSERT ผลที่ได้ไม่ใช่แถวข้อมูล แต่เป็น "รายงานผล" ซึ่งมีช่อง `insertId` (🟣 mysql2 กำหนด) = id ที่ MySQL สร้างให้แถวใหม่ จึงตั้งชื่อตัวแปรว่า `result` แทน `rows` ให้ไม่สับสน

▶️ **ทดสอบด้วย Thunder Client (ทำตามทีละข้อ)**
1. กดไอคอนสายฟ้า ⚡ ที่แถบซ้ายของ VS Code
2. กด **New Request**
3. ช่องซ้ายบน เปลี่ยน `GET` เป็น **`POST`**
4. ช่อง URL พิมพ์ `http://localhost:5000/api/topics`
5. กดแท็บ **Body** แล้วเลือก **JSON**
6. พิมพ์ในช่อง

```json
{ "title": "ทดสอบ", "start_date": "2026-11-01", "end_date": "2026-12-31" }
```

7. กด **Send**

✅ **ต้องเห็น:** มุมขวาบนขึ้น `Status: 201 Created` และคำตอบ

```json
{ "status": "success", "message": "เพิ่มหัวข้อสำเร็จ", "data": { "id": 3 } }
```

✅ **ลองส่งข้อมูลไม่ครบ:** แก้ body เป็น `{ "title": "" }` แล้ว Send ต้องได้ **400** "กรุณากรอกข้อมูลให้ครบ"

> 💾 กด **Save** เก็บ request ไว้ใน Collection (ตั้งชื่อ Collection ว่า `Eva`) จะได้กดทดสอบซ้ำได้ และใช้เป็นหลักฐานข้อ 7.6

> 🎉 นี่คือ **แพตเทิร์นที่ 3: เพิ่ม (ตอบ 201 พร้อม id ใหม่)**
> ```js
> const [result] = await pool.query("INSERT ...", [...]);
> ok(res, { id: result.insertId }, "เพิ่ม...สำเร็จ", 201);
> ```

### ขั้นที่ 3.10.7 PUT แก้ไขหัวข้อ

> 🎯 **ขั้นนี้จะได้:** แก้ชื่อและช่วงวันที่ของหัวข้อได้ (ใช้กำหนดช่วงเปิด-ปิดด้วย)

⌨️ **พิมพ์โค้ด:** เพิ่มใน `routes/topics.js` ต่อจาก route POST

```js
// PUT /api/topics/:id  (ใช้กำหนดช่วงเปิด-ปิดด้วย)
router.put("/:id", async (req, res) => {
  const { title, description, start_date, end_date } = req.body;
  const [result] = await pool.query(
    "UPDATE evaluation_topics SET title = ?, description = ?, start_date = ?, end_date = ? WHERE id = ?",
    [title, description, start_date, end_date, req.params.id]
  );
  if (!result.affectedRows) return fail(res, 404, "ไม่พบหัวข้อการประเมิน");
  ok(res, null, "แก้ไขหัวข้อสำเร็จ");
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 2 | ผูก **PUT** `/:id` | ฟอร์ม "แก้ไขหัวข้อ" และการตั้งวันเปิด-ปิดของ hr เรียก URL นี้ |
| 3 | แกะค่าจาก body เหมือน POST | ค่าใหม่ที่จะบันทึก |
| 4-7 | UPDATE มี `?` 5 ตัว: 4 ตัวแรกคือค่าใหม่ ตัวสุดท้ายคือ id ใน WHERE | แก้เฉพาะแถวที่ id ตรง |
| 6 | ค่า 5 ตัว เรียงตรงกับ `?` (**id อยู่ท้ายสุด** เพราะ `WHERE id = ?` อยู่ท้าย SQL) | ส่งค่าอย่างปลอดภัย |
| 8 | ถ้าไม่มีแถวไหนถูกแก้ ตอบ 404 แล้วจบ | กันกรณีแก้ id ที่ไม่มี |
| 9 | ตอบ 200 ไม่มี data (`null`) | หน้าเว็บโชว์ "แก้ไขหัวข้อสำเร็จ" |

> 🧩 syntax สอนไปแล้วทั้งหมด
> ข้อสังเกต: `result.affectedRows` (🟣 mysql2 กำหนด) = จำนวนแถวที่ถูกแก้ ถ้าเป็น `0` แปลว่าไม่มี id นี้ `!0` เป็นจริง จึงเข้า `if`

▶️ **ทดสอบ:** ใน Thunder Client ตั้ง **PUT** `http://localhost:5000/api/topics/3` Body JSON

```json
{ "title": "แก้แล้ว", "start_date": "2026-11-01", "end_date": "2026-12-31" }
```

✅ **ต้องเห็น:** 200 "แก้ไขหัวข้อสำเร็จ" แล้วเปิด /api/topics/3 ในเบราว์เซอร์ ชื่อต้องเปลี่ยนเป็น "แก้แล้ว"

✅ **ทดสอบ error handler จากขั้น 3.9.6:** ส่ง PUT เดิม แต่ใส่วันปิดก่อนวันเปิด

```json
{ "title": "แก้แล้ว", "start_date": "2026-12-31", "end_date": "2026-01-01" }
```

ต้องได้ **400** "ข้อมูลไม่อยู่ในช่วงที่กำหนด" (MySQL CHECK จับได้ แล้ว error handler แปลเป็น 400)

✅ **ทดสอบ id ที่ไม่มี:** เปลี่ยน URL เป็น `/api/topics/999` (ใช้วันที่ถูก) ต้องได้ **404**

### ขั้นที่ 3.10.8 DELETE ลบหัวข้อ

> 🎯 **ขั้นนี้จะได้:** ลบหัวข้อได้ และตัวชี้วัดในหัวข้อนั้นถูกลบตามอัตโนมัติ

⌨️ **พิมพ์โค้ด:** เพิ่มใน `routes/topics.js` ต่อจาก route PUT (ก่อน `export default router;`)

```js
// DELETE /api/topics/:id  (ตัวชี้วัดและคะแนนในหัวข้อนี้ถูกลบตาม)
router.delete("/:id", async (req, res) => {
  const [result] = await pool.query("DELETE FROM evaluation_topics WHERE id = ?", [req.params.id]);
  if (!result.affectedRows) return fail(res, 404, "ไม่พบหัวข้อการประเมิน");
  ok(res, null, "ลบหัวข้อสำเร็จ");
});
```

🔍 **อ่านโค้ดทีละบรรทัด**

| บรรทัด | ทำอะไร | เอาไว้ใช้ทำอะไร |
|---|---|---|
| 2 | ผูก **DELETE** `/:id` | ปุ่ม "ลบ" ในหน้าจัดการหัวข้อของ hr เรียก URL นี้ |
| 3 | ลบแถวที่ id ตรง | ลบหัวข้อออกจากฐานข้อมูล |
| 4 | ไม่มีแถวถูกลบ = ไม่พบ ตอบ 404 | กันกรณีลบซ้ำ หรือ id ผิด |
| 5 | ตอบ 200 | หน้าเว็บโชว์ "ลบหัวข้อสำเร็จ" แล้วโหลดรายการใหม่ |

📖 **ทำไมไม่ต้องเขียนโค้ดลบตัวชี้วัด?** ในบท 02 ตาราง indicators ตั้ง `ON DELETE CASCADE` ไว้ MySQL จะลบตัวชี้วัดของหัวข้อนี้ให้เอง

▶️ **ทดสอบ:** Thunder Client ตั้ง **DELETE** `http://localhost:5000/api/topics/3` (ไม่ต้องมี Body)

✅ **ต้องเห็น:** 200 "ลบหัวข้อสำเร็จ" กด Send ซ้ำอีกครั้ง ต้องได้ **404** (เพราะลบไปแล้ว)

> 🎉 นี่คือ **แพตเทิร์นที่ 4: แก้ไข / ลบ (ไม่มีแถวถูกแก้ = ไม่พบ)**
> ```js
> const [result] = await pool.query("UPDATE/DELETE ... WHERE id = ?", [..., req.params.id]);
> if (!result.affectedRows) return fail(res, 404, "ไม่พบ...");
> ok(res, null, "แก้ไข...สำเร็จ");
> ```

## 3.11 ทบทวนท้ายบท

### ขั้นที่ 3.11.1 ข้อมูลเข้ามาได้ 3 ทาง

> 🎯 **ขั้นนี้จะได้:** แยกได้ว่าค่าที่ส่งมา อ่านจาก `req.params`, `req.query` หรือ `req.body` (เกณฑ์ 6.10)

| ที่มา | ตัวอย่าง | อ่านด้วย | ได้ค่า | ใช้กับงานแบบไหน |
|---|---|---|---|---|
| ใน path (route มี `:id`) | `/api/topics/3` | `req.params.id` | `"3"` | ระบุว่า "ข้อมูลตัวไหน" (ดู/แก้/ลบ 1 รายการ) |
| หลังเครื่องหมาย `?` (query string) | `/api/users?role=evaluatee` | `req.query.role` | `"evaluatee"` | กรอง / ค้นหา |
| ใน Body (POST / PUT) | `{ "title": "ก" }` | `req.body.title` | `"ก"` | ข้อมูลจากฟอร์มที่จะบันทึก |

> 💡 ค่าจาก `params` และ `query` เป็น **ข้อความเสมอ** แม้จะเป็นตัวเลข (`"3"` ไม่ใช่ `3`)
> ตัวอย่าง: `PUT /api/topics/5` body `{"title":"ใหม่"}` → เลข 5 อ่านจาก `req.params.id` ส่วน "ใหม่" อ่านจาก `req.body.title`

| `req.body` เป็น `undefined` | ลืม `express.json()` หรือไม่ได้เลือก Body เป็น JSON | ตรวจ app.js และ Thunder Client |
| `Cannot set headers after they are sent` | ตอบกลับ 2 ครั้ง (ลืม `return` หน้า `fail`) | ใส่ `return fail(...)` |
| เบราว์เซอร์หมุนค้าง ไม่มีคำตอบ | route ไม่ได้เรียก `ok` หรือ `fail` | ทุก route ต้องตอบกลับ 1 ครั้ง |
| ทุก URL ได้ 404 | วางบรรทัด 404 ไว้เหนือ route | ย้ายบรรทัด 404 ลงไปล่างสุด (ก่อน error handler) |
| วันที่เลื่อนไป 1 วัน | ไม่ได้ใส่ `dateStrings: true` | เพิ่มใน db.js |
| ภาษาไทยในคำตอบเพี้ยน | ส่ง body จาก terminal (curl) บน Windows | ใช้ Thunder Client แทน |
