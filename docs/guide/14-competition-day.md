### ขั้นที่ 14.2.1 ใครทำอะไร และใช้ฐานข้อมูลร่วมกัน

> 🎯 **ขั้นนี้จะได้:** แต่ละคนรู้ว่ารับผิดชอบเส้นไหน และทุกเครื่องเห็นข้อมูลชุดเดียวกัน

ทุกคนเขียน**ทั้ง frontend และ backend** ของเส้น API ที่ตัวเองรับผิดชอบ ดูว่าแต่ละเส้นใช้ไฟล์ไหน บรรทัดไหน ได้ในแผนที่ API ทุกคนอ่าน [shared.html](../api-map/shared.html) (ส่วนกลาง: ลำดับงาน โค้ดส่วนกลาง แม่แบบ CRUD) ก่อน แล้วค่อยเปิดไฟล์ของตัวเอง

| คนที่ | ส่วนกลาง (ทำชั่วโมงแรก) | เส้น API ของตัวเอง | แผนที่ API |
|---|---|---|---|
| 1 | สร้างโปรเจกต์ + backend ส่วนกลาง (app/server, db, middleware, response, password, routes/auth) + Field, Modal, Layout, StatusBadge | งานบุคลากร: users, topics, indicators, assignments | [person-1-hr.html](../api-map/person-1-hr.html) |
| 2 | **เปิด MySQL กลางที่เครื่องตัวเอง** + schema.sql + หน้า login, register, change-password + `utils/dataCheck.js` | profile, ประเมินตนเอง, หลักฐาน, สำรอง/กู้คืน, Dashboard | [person-2-evaluatee.html](../api-map/person-2-evaluatee.html) |
| 3 | frontend lib (api, auth, validate, format, constants) + schemas ฝั่งหน้าเว็บ + `utils/score.js` | กรรมการ (ให้คะแนน, ร่าง, ลายเซ็น, ยืนยัน) + รายงาน + PDF | [person-3-committee.html](../api-map/person-3-committee.html) |

📖 **ส่วนกลาง** คือโค้ดที่ทุกคนใช้ร่วมกัน แบ่งกันทำคนละชิ้น เพื่อให้รวมกับเส้นของตัวเองแล้วได้งานใกล้กัน (คนละประมาณ 1,350 บรรทัด) คนที่ 3 ได้ส่วนกลางน้อยที่สุด เพราะเส้นของคนที่ 3 ยากที่สุด (คำนวณคะแนน, ลายเซ็น, รายงาน)

**ใช้ MySQL บนเครื่องคนที่ 2 เครื่องเดียว** (backend ของทุกคนรันบนเครื่องตัวเอง แต่ต่อ DB เดียวกัน)
- เครื่องคนที่ 1 และ 3 แก้ `.env` เป็น `DB_HOST=<IP เครื่องคนที่ 2>` (ดู IP ด้วย `ipconfig`) และ**ไม่ต้องเปิด MySQL ของตัวเอง** ส่วน `DB_PASSWORD` ต้องตรงกับเครื่องคนที่ 2
- ข้อดี: คนที่ 1 สร้างหัวข้อ/ตัวชี้วัด/มอบหมายแล้ว คนที่ 2 และ 3 เห็นข้อมูลนั้นทันที ไม่ต้องสร้างข้อมูลทดสอบ 3 รอบ
- ทำไมต้องเป็นเครื่องคนที่ 2: ฟังก์ชันสำรองข้อมูลเรียก `docker exec` ไปที่กล่อง MySQL ซึ่งต้องอยู่บนเครื่องเดียวกับ backend ที่กดสำรอง
- ไฟล์หลักฐานเก็บใน `backend/uploads` ของเครื่องที่รับอัปโหลด ทดสอบดาวน์โหลดไฟล์ต้องใช้ backend เครื่องเดียวกับที่อัปโหลด

### ขั้นที่ 14.3.1 Backend: route CRUD (บท 03-05)

> 🎯 **ขั้นนี้จะได้:** แม่แบบ route 5 ตัวที่ใช้ซ้ำได้ทุกตาราง

```js
import { Router } from "express";
import pool from "../db.js";
import { ok, fail } from "../utils/response.js";
import { verifyToken, requireRole } from "../middleware/auth.js";
import { validate } from "../middleware/validate.js";
import { xSchema } from "../schemas/x.js";

const router = Router();
router.use(verifyToken, requireRole("hr"));

router.get("/", async (req, res) => {                                   // อ่านทั้งหมด
  const [rows] = await pool.query("SELECT * FROM x ORDER BY id");
  ok(res, rows);
});
router.get("/:id", async (req, res) => {                                // อ่าน 1
  const [rows] = await pool.query("SELECT * FROM x WHERE id = ?", [req.params.id]);
  if (!rows[0]) return fail(res, 404, "ไม่พบข้อมูล");
  ok(res, rows[0]);
});
router.post("/", validate(xSchema), async (req, res) => {               // เพิ่ม
  const [result] = await pool.query("INSERT INTO x (a, b) VALUES (?, ?)", [req.body.a, req.body.b]);
  ok(res, { id: result.insertId }, "เพิ่มสำเร็จ", 201);
});
router.put("/:id", validate(xSchema), async (req, res) => {             // แก้
  const [result] = await pool.query("UPDATE x SET a = ?, b = ? WHERE id = ?", [req.body.a, req.body.b, req.params.id]);
  if (!result.affectedRows) return fail(res, 404, "ไม่พบข้อมูล");
  ok(res, null, "แก้ไขสำเร็จ");
});
router.delete("/:id", async (req, res) => {                             // ลบ
  const [result] = await pool.query("DELETE FROM x WHERE id = ?", [req.params.id]);
  if (!result.affectedRows) return fail(res, 404, "ไม่พบข้อมูล");
  ok(res, null, "ลบสำเร็จ");
});

export default router;
// อย่าลืม: app.use("/api/x", xRoutes) ใน app.js
```

| ส่วน | จำ |
|---|---|
| ด่าน | `router.use(verifyToken, requireRole(...))` บนสุด (บท 04 ขั้น 4.7) |
| อ่าน 1 / แก้ / ลบ ไม่พบ | 404 |
| เพิ่มสำเร็จ | **201** + `{ id: result.insertId }` |
| ตรวจ body | `validate(schema)` ก่อน async |

### ขั้นที่ 14.3.2 Frontend: หน้า CRUD (บท 08)

> 🎯 **ขั้นนี้จะได้:** แม่แบบหน้ารายการ + ปุ่มเพิ่ม/ลบ + Modal

```jsx
import { useEffect, useState } from "react";
import api, { errorMessage } from "@/lib/api";
import { useAuth } from "@/lib/auth";
import Layout from "@/components/Layout";
import XModal from "@/components/XModal";

export default function XPage() {
  const user = useAuth(["hr"]);
  const [items, setItems] = useState([]);
  const [error, setError] = useState("");
  const [editing, setEditing] = useState(null);          // null ปิด, {} เพิ่ม, item แก้

  const load = () => api.get("/x").then((res) => setItems(res.data.data)).catch((err) => setError(errorMessage(err)));
  useEffect(() => { if (user) load(); }, [user]);

  const remove = async (item) => {
    if (!confirm(`ลบ ${item.name} ?`)) return;
    try { await api.delete(`/x/${item.id}`); load(); } catch (err) { alert(errorMessage(err)); }
  };

  if (!user) return null;
  return (
    <Layout user={user}>
      {error && <div className="alert alert-error mb-4">{error}</div>}
      <button className="btn btn-primary" onClick={() => setEditing({})}>เพิ่ม</button>
      <div className="overflow-x-auto"><table className="table">...{items.map((i) => <tr key={i.id}>...</tr>)}</table></div>
      {editing && <XModal item={editing} onClose={() => setEditing(null)} onSaved={() => { setEditing(null); load(); }} />}
    </Layout>
  );
}
```

| ส่วน | จำ |
|---|---|
| `editing` | `null` = ปิด Modal, `{}` = เพิ่ม, ข้อมูล = แก้ (บท 08 ขั้น 8.1) |
| `load` | ทุก `.then` ต้องมี `.catch` |
| `if (!user) return null` | ก่อน return JSX เสมอ |
| ตาราง | ครอบ `overflow-x-auto` (มือถือ) |

### ขั้นที่ 14.3.3 Frontend: Modal ฟอร์ม (บท 08)

> 🎯 **ขั้นนี้จะได้:** แม่แบบฟอร์มเพิ่ม/แก้ด้วย React Hook Form + Zod

```jsx
export default function XModal({ item, onClose, onSaved }) {
  const [error, setError] = useState("");
  const { register, handleSubmit, formState: { errors, isSubmitting } } = useForm({
    resolver: validateWith(xSchema),
    defaultValues: formValues({ name: "", ...item }),
  });
  const onSubmit = async (data) => {
    try {
      if (item.id) await api.put(`/x/${item.id}`, data);
      else await api.post("/x", data);
      onSaved();
    } catch (err) { setError(errorMessage(err)); }
  };
  return (
    <Modal title={item.id ? "แก้ไข" : "เพิ่ม"} onClose={onClose}>
      <form onSubmit={handleSubmit(onSubmit)}>
        {error && <div className="alert alert-error">{error}</div>}
        <Field label="ชื่อ" error={errors.name}><input className="input w-full" {...register("name")} /></Field>
        <div className="modal-action">
          <button type="button" className="btn" onClick={onClose}>ยกเลิก</button>
          <button className="btn btn-primary" disabled={isSubmitting}>บันทึก</button>
        </div>
      </form>
    </Modal>
  );
}
```

| ส่วน | จำ |
|---|---|
| `resolver: validateWith(schema)` | ห้ามใช้ @hookform/resolvers (บท 07 หัวข้อ 7.7) |
| `formValues(...)` | แปลง null เป็น `""` กัน warning controlled input (บท 07 ขั้น 7.11.2) |
| `item.id` มีไหม | แยกเพิ่ม (POST) / แก้ (PUT) ด้วยฟอร์มเดียว |
| ปุ่มยกเลิก | `type="button"` ไม่งั้นส่งฟอร์ม |

## 14.7 แผนซ้อม

### ขั้นที่ 14.7.1 ซ้อม 3 รอบก่อนแข่ง

> 🎯 **ขั้นนี้จะได้:** ทำระดับ 1+2 เสร็จใน 6 ชั่วโมงโดยไม่เปิดคู่มือ

| รอบ | วิธีซ้อม | เป้าหมาย |
|---|---|---|
| 1 | ทำตามคู่มือ เปิดเฉลยได้ จับเวลา | รู้ว่าตัวเองช้าตรงไหน |
| 2 | เปิดได้แค่แผ่นสรุปแพตเทิร์น (14.3) | ระดับ 1 เสร็จใน 4.5 ชั่วโมง |
| 3 | **จำลองวันแข่งจริง:** ไม่เปิดอะไรเลย ปิดเน็ต 6 ชั่วโมง ครูเป็นกรรมการตรวจตามเกณฑ์ + ถามคำถาม | ระดับ 1+2 เสร็จ + นำเสนอได้ใน 20 นาที |

หลังแต่ละรอบ: จดส่วนที่ติดนานที่สุด 3 อย่าง แล้วฝึกเฉพาะส่วนนั้นซ้ำ

## ❗ ปัญหาที่พบบ่อยในวันแข่ง

| ปัญหา | ป้องกัน/แก้ |
|---|---|
| ลืม `exclude: join` หน้าเว็บ error 500 ทั้งหมด | ใส่ตั้งแต่ตั้งค่าโปรเจกต์ (จำข้อ 10) |
| วันที่ของหัวข้อไม่ครอบคลุมวันแข่ง หัวข้อปิด | ตั้ง start_date/end_date ให้ครอบคลุมวันแข่ง |
| ทำฟีเจอร์ใหม่จนนาทีสุดท้าย แล้วระบบพัง | หยุดเพิ่มฟีเจอร์ตอน 14.30 |
| ไม่ได้ push จนหมดเวลา | push ตั้งแต่ชั่วโมงแรก และทุกครั้งที่ commit |
| `.env` หลุดขึ้น Git | สร้าง .gitignore ก่อน commit แรก (บท 01) |
| ติด error นานเกิน 10 นาที | ข้ามไปทำส่วนอื่นก่อน แล้วกลับมาทีหลัง (หรือให้เพื่อนช่วยดู) |
| port ชน | ปิด Terminal ที่ไม่ใช้ / เปลี่ยน port ใน .env |
| เครื่องคนที่ 1 หรือ 3 ต่อฐานข้อมูลไม่ได้ (`ECONNREFUSED`, `ETIMEDOUT`) | ตรวจ `DB_HOST` เป็น IP เครื่องคนที่ 2 และเครื่องนั้นอนุญาต port 3306 ใน Windows Firewall (ตรวจด้วย `Test-NetConnection` ขั้น 14.1.1) |
| `git pull` แล้วขึ้น `CONFLICT` | เปิดไฟล์ใน VS Code เลือก Accept Both แล้วลบส่วนที่ซ้ำ จากนั้น `git add .` และ `git commit` |
| ข้อมูลหายกลางคัน | มีคนกู้คืนข้อมูลหรือ `down -v` ที่เครื่องคนที่ 2 (กฎเหล็กข้อ 3) |
