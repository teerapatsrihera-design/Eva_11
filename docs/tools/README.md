# เครื่องมือของครู (docs/tools)

ใช้สร้างและตรวจเอกสาร และทดสอบว่าคู่มือยังตรงกับระบบจริง **ไม่ใช่ส่วนของระบบที่นักเรียนส่งแข่ง** นักเรียนไม่ต้องใช้โฟลเดอร์นี้

`marked` ใน `package.json` (ตัวแปลง Markdown เป็น HTML) ใช้เฉพาะเครื่องมือนี้ ไม่ได้อยู่ใน backend หรือ frontend ส่วน stack ของระบบยังเหมือนเดิม

## ติดตั้งครั้งแรก

```bash
cd docs/tools
npm install
```

ต้องมี Node.js 24, Docker Desktop และ Microsoft Edge (ใช้เปิดหน้าเว็บแบบไม่มีหน้าต่าง) ถ้า Edge อยู่ที่อื่น ให้ตั้งตัวแปร `EDGE` เป็นที่อยู่ของ `msedge.exe`

## ใช้เมื่อไร

| ทำอะไร | คำสั่ง (ในโฟลเดอร์นี้) | ใช้เมื่อ |
|---|---|---|
| สร้างแผนที่ API ใหม่ | `npm run map` | **แก้โค้ดใน backend/frontend** (เลขบรรทัดในแผนที่ API จะคลาด) |
| ตรวจแผนที่ API ในเบราว์เซอร์ | `npm run map:check` | หลัง `npm run map` |
| สร้าง eva-guide.html ใหม่ | `npm run guide` | **แก้ไฟล์ `docs/guide/*.md`** |
| ทดสอบคู่มือกับระบบ (แบบ dev) | `npm run test:dev` | แก้โค้ดหรือคู่มือแล้วอยากรู้ว่าตัวเลขในคู่มือยังตรงไหม (ประมาณ 5 นาที ไม่แตะ `eva_mysql`) |
| ทดสอบกับระบบที่ deploy | `sh run-tests.sh docker --wipe` | หลัง `docker compose up -d --build` **ล้างข้อมูลใน eva_mysql ทั้งหมด** แล้วคืนเป็นตารางเปล่า |
| ทดสอบโปรเจกต์ที่นักเรียนสร้างเอง | `APP_ROOT=C:/Eva_Try sh run-tests.sh dev` | อยากรู้ว่าโปรเจกต์ของนักเรียนทำงานได้ครบเหมือนเฉลยไหม (โฟลเดอร์ต้องมี backend/frontend โครงเดียวกัน และปิด `next dev` ของโฟลเดอร์นั้นก่อน) |
| เก็บ response จริงใหม่ | `npm run capture` | เปลี่ยนรูปแบบ response ของ API (ตัวอย่าง response ในแผนที่ API มาจาก `captures.json`) |

คำสั่ง `test:*` และ `capture` รันใน **Git Bash** (เป็นสคริปต์ `sh`)

## ไฟล์ในโฟลเดอร์

| ไฟล์ | หน้าที่ |
|---|---|
| `spec1.mjs`, `spec2.mjs` | รายการเส้น API ของแต่ละคน และชิ้นโค้ดที่แต่ละเส้นใช้ (อ้างด้วยข้อความในไฟล์จริง ไม่ใช่เลขบรรทัด) |
| `owners.mjs` | รายชื่อไฟล์ทั้งหมดของระบบ และใครเป็นคนทำ (ใช้ทำป้ายเจ้าของและส่วน "ไฟล์เต็ม" ในแผนที่ API) **เพิ่มไฟล์ใหม่ในโปรเจกต์ต้องเพิ่มที่นี่ด้วย** ไม่งั้น `npm run map` จะแจ้งว่าไม่มีเจ้าของ |
| `lib.mjs`, `gen.mjs` | หาเลขบรรทัดจริงจากไฟล์โค้ด แล้วเขียนเป็น Markdown ชั่วคราวใน `.out/` |
| `build-map.mjs` | แปลง Markdown เป็น `docs/api-map/*.html` 4 ไฟล์ (shared + คนที่ 1-3) หน้าตาเดียวกับ eva-guide.html |
| `verify.mjs`, `check-map.mjs` | ตรวจว่าครบ 47 เส้น โค้ดตรงไฟล์จริงทุกบรรทัด ลิงก์ไม่เสีย และเปิดในเบราว์เซอร์ได้ |
| `render-guide.mjs`, `check-guide.mjs`, `check-guide-html.mjs` | สร้าง `docs/guide/eva-guide.html` จากไฟล์ .md แล้วตรวจลิงก์และหน้าเว็บ |
| `replay.mjs` | ทำตามคู่มือบท 03-06 ผ่าน API บน DB ว่าง แล้วเทียบตัวเลขกับที่คู่มือเขียน (103 ข้อ) |
| `ui-test.mjs` | กดหน้าเว็บจริงตามคู่มือบท 07-12 (122 ข้อ) |
| `flow.mjs`, `captures.json` | ยิงทุกเส้นแล้วเก็บ request/response จริงไว้ใช้ในแผนที่ API |
| `run-tests.sh` | เตรียม DB ทดสอบ รันทดสอบ แล้วลบไฟล์ที่ทดสอบสร้างใน `backend/uploads` และ `backend/backups` |
| `.out/` | ไฟล์ชั่วคราวและผลทดสอบ (ไม่ขึ้น Git) |

- ข้อมูลทดสอบใช้หัวข้อช่วงวันที่ 2026-11-01 ถึง 2026-12-31 ถ้ารันหลังวันที่ 31 ธ.ค. 2026 หัวข้อจะปิดและการทดสอบบางข้อจะไม่ผ่าน ต้องเลื่อนวันที่ในคู่มือและในสคริปต์ทดสอบพร้อมกัน
- เครื่องที่มี IDM อาจดักไฟล์ PDF ตอนทดสอบดาวน์โหลด (สคริปต์ใช้ไฟล์ PNG ตรวจแทน)
